# Storybook

Каталог UI Kit (`@hcengineering/ui`) и design-библиотека: визуальные компоненты и экраны макетов на живых стилях темы, без клиента платформы.

## Запуск

```bash
cd dev/storybook
pnpm storybook
```

Открыть http://localhost:6006. Тема, акцент и язык переключаются в панели инструментов Storybook.

Статическая сборка: `pnpm build-storybook`, результат в `storybook-static/`.

## Разделы

| Раздел | Где | Что |
|---|---|---|
| UI Kit | `src/ui-kit` | Компоненты `packages/ui/src/ui-kit` |
| Kit | `src/design/kit/<Категория>` | Визуальная библиотека: Workbench, Actions, Forms, Status, TagsAndFilters, People, Tracker, Settings, Chat, Login. Пропсы - данные предметной области (`kit/types.ts`), без раскладки |
| Screens / ... | `src/design/generated` | Принятое текущее состояние UI (`dev/design/screens/current`): Workbench (оболочка и её элементы), Tracker (канбан, список задач, мои задачи, страница задачи, диалог новой задачи). История `Canvas` на страницу, по истории на фрейм, общий `Screens / Canvas` |

Библиотека `src/design/kit` - первичный источник: компоненты продукта доводятся до неё.

## Экраны макетов

Процесс:

1. Storybook описывает текущее положение: раздел `Screens` и библиотеку компонентов `Kit`. Те же скрипты дают библиотеку и экраны в Penpot и pen.dev.
2. Новые макеты или переработку готовых экранов делают в Penpot или pen.dev на этих компонентах. Макеты задач (например FUSIO-1613) живут только там, в Storybook их нет.
3. Когда вид утверждён, сценарий экрана из Penpot или pen.dev на компонентах переносится в Storybook как финальный вариант, и по нему меняют реализацию.

Всё, что показано в Storybook, имеет синхронный код, который строит тот же вид в Penpot и pen.dev; экран только на Svelte без скрипта не принимается.

Экраны описаны скриптами `dev/design/screens/<папка>/*.js`, список сборок - `dev/design/design.json`. Файл с ключом `"storybook": "<раздел>"` получает истории с этим префиксом (`Screens` - текущее состояние); файл без ключа, как макеты задач, в Storybook не попадает. Те же скрипты рисуют макеты в Penpot (`dev/penpot`) и pen.dev (`dev/pen`, файлы `.pen` и библиотека компонентов с теми же именами `<Категория>/<Имя>` собираются в `../foundation-tasks/design`). Здесь их выполняет записывающий кит `src/design/generated/recorder.ts`: вместо фигур он строит дерево компонентов, а `Render.svelte` рисует его компонентами `src/design/kit`.

- Правка скрипта экрана видна сразу, Storybook перезагрузит историю.
- Поменялось число фреймов или страниц, либо файл в `design.json` - заново создать файлы историй: `pnpm generate-screens`.
- Данные: `src/design/demo/demo.generated.json`, его пишет `node dev/design/generate.mjs demo` из демо-набора (нужен чекаут `../foundation4-demo`).

## Окно и холст

- `src/design/kit/Frame.svelte` - хром окна приложения (три кнопки, заголовок, тень, фон рабочей области). История каталога `Kit/...` целиком лежит в одном окне (`kit/FramedSections.svelte`), каждый фрейм экрана тоже.
- Попапы в каталоге показаны раскрытыми под кнопкой-триггером (`kit/demo/MenuDemo.svelte`).
- `generated/Canvas.svelte` - холст в координатах x, y из скриптов экранов (запись `pos` у фрейма). Над фреймом подпись, клик по ней открывает историю фрейма. Ctrl/Cmd + колесо - зум к курсору, колесо или перетаскивание - сдвиг, кнопки "Fit all" и "100%". Все страницы на общем холсте стоят слева направо.
- Фрейм рисуется, когда подошёл к видимой области (IntersectionObserver); дальше остаётся в DOM.

Особенности и найденные ловушки - `docs/memory/storybook.md`.
