# Task boards (FUSIO-1623)

Область: [Доски трекера](../features/tracker-boards.md)

- Колонка доски в `KanbanView` - один `AggregateValue` (name = id колонки, values = статусы, и у каждого значения тоже name = id колонки: `groupBy` переименовывает группу статуса в имя значения, с пустым именем все задачи падали в группу `''` и колонки были пусты): так работают `groupBy`, `stateKey`, пересчёт групп без прав на merge; `controlKey` доски задаёт localStorage для свёрнутых колонок/дорожек, объединения колонок для досок нет (кнопка скрыта).
- `FilterQuery` (`plugins/view-resources/src/filter.ts`) ключует живые запросы вложенных фильтров по `Filter.index` глобально: условия досок получают случайный индекс (`FilterConditions`), иначе вложенные фильтры двух условий делят один запрос.
- Дорожки доски и цвета рамки = множества id из живых запросов (`ConditionMatches`); дорожки собираются в `swimLanes` только когда все запросы ответили, иначе Kanban шлёт запросы карточек в последнюю дорожку.
- Проектный канбан не перенаправляет на доску (решение пользователя 2026-10-26); досок в задачах проекта нет (решение 2026-10-28): страницу доски открывают только раздел "Доски" навигатора и переключатель. Первая доступная доска (`pickDefaultBoard`) открывается лишь по пути `tracker/boards` без id.
- Права на правку доски (автор, `editors`) проверяются только в UI; сервер документ `Board` в `core.space.Workspace` не защищает.
- Фокус карточки = класс `.selection` у `.card-container` (KanbanRow): внутренняя тень `inset 0 0 1px 1px primary-edit-border-color`; наведение мышью тоже шлёт `obj-focus`, отдельного вида hover нет. Рамка цветового правила - `inset 2px` у вложенного `.tracker-card` (KanbanView) и по порядку отрисовки перекрывает кольцо фокуса (вывод по коду).
- Во время drag все ячейки дорожек получают `.drop-target`, целевая не выделена; `--theme-drop-zone-bg-color` нигде не задан (работает запасной `theme-button-hovered`). WIP-лимит бросок не блокирует, блокирует только workflow (`isBlocked`, `.drop-disabled`). Превышение WIP-лимита красит не только число в заголовке, но и область карточек колонки (решение пользователя 2026-10-28: одного числа мало).
- До 2026-10-26 перенос в другую дорожку доски писал в задачу мусорное поле `board` (`swimLaneUpdateProps` для ключа `board` возвращал `{ board: <id дорожки> }`), а карточка возвращалась в дорожку по фильтру. Теперь `board` в `IMMUTABLE_SWIM_FIELDS`, и `Kanban` не берёт карточку в дорожку без правки (`laneTakes`). Задачи, перенесённые раньше, могут хранить поле `board`.
- Строки досок в `BoardsNav.svelte`: кнопка `NavItem` растягивается на ширину строки только как flex-элемент колонки, поэтому обёртка `data-id="boardsNav"` - `display: flex; flex-direction: column` (иначе подсветка выбранной шла по ширине содержимого). Иконка у всех - `task.icon.Kanban`, закреплённая отмечена маленьким значком справа (в макете Storybook закрепление в навигаторе не показано).
- Статусы в настройках доски: `activeProjects` (task-resources) не содержит архивных проектов, а `getStates(undefined)` молча даёт `[]`; поэтому `BoardSettings` берёт проекты своим запросом с `showArchived`, а чипы колонок - из `statusStore` (иначе статус проекта, убранного с доски, исчезал из колонки). На живом стенде пустых статусов у активного проекта не воспроизвелось.
- `parseFilters` (`plugins/view-resources/src/filter.ts`) - граница для условий из документов: условие не той формы отбрасывается, повторный или пустой `index` заменяется; `FilterSection` и presenter'ы значений (`PriorityFilterValuePresenter`) падали на чужой форме `value`. Значение фильтра приоритета хранится парами `[[ключ, [значения]]]`.
- `Board.cardFields` без `@Prop`: модель не меняется, поле хранится в документе без перезапуска сервера (проверено на dev-стенде 2026-10-26). Нет поля - карточка доски берёт видимость из config вида (`enabledConfig`), как до настройки; флажки на вкладке при этом все отмечены.
- "Дни в колонке" и условие "в статусе > N дн." не сделаны: у задачи нет времени входа в статус, только `modifiedOn` (меняется от любой правки); элементы спрятаны флагом `tracker-issue-stats`.
- Образец на вкладке "Карточка" не перегружается от кликов: `loadSample` зависит только от строки `[projects, filter]` (Svelte не инвалидирует равную строку).
- Образец карточки в настройках (`IssueKanbanCard` с `preview`): пустой компонент нельзя показать через `ComponentEditor` - пустой `ComponentSelector` пишет "Без компонента", поэтому пример - отдельная `Button` с иконкой и `tracker.string.Component`; пустой этап `MilestoneEditor` сам пишет "Этап". Метка-пример - `TagReferencePresenter` (экспорт `tags-resources`), `LabelsPresenter` без меток ничего не рисует.
- Флаги `tracker-board-next` (элементы настроек без поля в модели) и `tracker-issue-stats` (всё, что требует времени в статусе) лежат в `alwaysDisabled` (`packages/presentation/src/utils.ts`), а не в `DisabledFeatures`: `DisabledFeatures` приходит из конфига стенда, а "не готово" должно быть выключено везде без конфига; включить - убрать id из списка. Спрятанные элементы рисуются как в макете, но состояние локальное и нигде не пишется; у каждого условия комментарий с именем недостающего поля.
- Образец цветов (`RulesTab`): `ConditionMatches` с областью `boardQuery` (проекты и фильтр доски), для правила берётся первая задача, подходящая под него и не подходящая ни под одно правило выше (`pickRuleSamples`), иначе рамка была бы чужая.
- Карточка доски открывается короткой ссылкой `tracker/<ID>`: `mergeLoc` (`Workbench.svelte`) достраивал путь из `currentSpace`/`currentSpecial` и терял хвост (id доски: `boards/<id>` становился `boards/issues`, в проекте `issues/<доска>` терял сегмент), поэтому после открытия и закрытия задачи страница показывала "Доска не найдена". Хвост теперь берётся из `getCurrentResolvedLocation()`, пока совпадают сегменты 3 и 4.
- Кольцо фокуса карточки (`.modern.selection` в `KanbanRow`) одинаково для мыши и клавиатуры (решение пользователя 2026-10-26): наведение мышью тоже ставит фокус (`obj-focus`) и тоже рисует кольцо, фон карточки не меняется. Кольцо - `outline` снаружи карточки, поэтому `Scroller` колонки получил поля 0.25rem. Кольцо полупрозрачное (2026-10-28): сплошной цвет был слишком ярким.
- Своей сетки у доски нет (решение пользователя 2026-10-28): отступы и ширина колонок как у обычного канбана, от плотности карточек зависят только отступы (`densityGrid` в `KanbanView`), ширина колонки всегда 20rem.
- Чип "N проект недоступен" в `BoardView`: проект из `board.projects`, которого нет в ответе запроса с `showArchived`, скрыт от пользователя (нет доступа), архивный приходит с `archived: true`. Идентификатор известен только у архивного.
- Статусы колонки доски открываются кликом по заголовку (решение пользователя 2026-10-28), не тултипом: всплывающий при наведении блок мешал карточкам; при наведении - короткая подсказка сверху.
- `Board.swimLaneBy` выключается записью `null`, а не `undefined`: `client.update` с `undefined` теряет ключ при сериализации, и на сервере значение остаётся. Поле без `@Prop`, как `cardFields`, модель не меняется.
- Полноэкранный режим доски (`fullscreenStore`, `workbench-resources`): панель виджетов прячется CSS-правилом на родителе (`.fullscreen > :not(.workbench-container)`), а не обёрткой и не `{#if}`. `Separator` считает размеры по `parentElement.children`, обёртка ломает его, а размонтирование виджетов оборвало бы звонок.
- Проекты доски, добавленные в "Основном", не появлялись до переоткрытия настроек: `SpacesMultiPopup` делал `push` в переданный `selectedSpaces`, то есть прямо в `board.projects` документа. `createQuery` сравнивает новый запрос со старым (`deepEqual`), а старый держал тот же массив, уже изменённый, поэтому запрос проектов не перезапускался. Попап теперь собирает новый массив.
- Кнопка опций вида пропадала после возврата из настроек доски: список видов уже в кэше, `ViewletSelector` ставит вид прямо при сборке шапки, а `bind:viewlet` у `ViewletSettingButton`, созданной раньше с пустым видом, затирает его. Помогает только создавать кнопку, когда вид уже известен (`{#if viewlet !== undefined}` в `IssuesView`). Односторонний `{viewlet}` вместо `bind` вешает страницу: каждый `$set` объекта заново считает `viewOptions`, `FilterBar` получает новый объект, круг без конца ("Invalid array length" в `make_dirty`).
- Шапка доски (решение пользователя 2026-10-28): без переключателя видов и опций вида, в одну строку; на доске сортировка - `Board.orderBy` из настроек, плотность - ползунок в шапке. Выделение карточки канбана - как у карточки Диска (рамка 30% фирменного цвета и тень), не кольцо. Дорожки по фильтрам спрятаны флагом `tracker-board-next`. Доски открываются только из раздела "Доски" навигатора, доски в задачах проекта удалены. Позже в тот же день убраны заголовок и переключатель досок (доску показывает навигатор): строка начинается с поиска и фильтра, `Header` в одну строку держит место заголовка растягиваемым, поэтому `SpaceHeader` с `searchFirst` кладёт их в место заголовка, а группу поиска прячет (`hideSearch`). "Настройки доски" - пункт меню "⋮".
- Создание доски (решение 2026-10-28): мастер `CreateBoard.svelte` как создание проекта (`WizardDialog`, 2 шага: "Основное" и "Колонки"); статусы в `ColumnsTab` и в мастере, и в настройках - прежние плашки (чипы пробовали, пользователь вернул плашки). Мгновенное создание отвергнуто (пользователи не понимали, что произошло), одностраничное окно (название и видимость, одна пустая колонка) отвергнуто: колонки, участники и фильтр нужны при создании. Колонка по умолчанию одна, пустая (просьба пользователя), колонки по категориям статусов отвергнуты; после создания открывается доска, не настройки.
- Права досок (решение пользователя 2026-10-28, вариант "PersonSpace"): личная доска (`visibility: 'me'`) лежит в приватном PersonSpace автора, `SpaceSecurityMiddleware` скрывает её от других; `BoardMiddleware` (`server-plugins/tracker`) проверяет только запись. Смена видимости = `TxUpdateDoc` с `space` (`SpaceUpdate`), `_id` не меняется, `BoardPreference.attachedTo` остаётся верным.
- Крайние случаи личных досок: проверка записи и рассылка в `SpaceSecurityMiddleware` идут по `tx.objectSpace` (старое пространство), а не по `operations.space`. Поэтому `all` -> `me` рассылается всем (старое пространство - воркспейс), чужие клиенты скрывают доску по `visibility` через `isBoardAvailable`, а `me` -> `all` рассылается только автору. Поэтому `BoardMiddleware` после переноса доски в другое пространство кладёт в рассылку `createBroadcastEvent([tracker.class.Board])` (`WorkspaceEvent.BulkUpdate`): все клиенты перечитывают запросы досок, а сервер отдаёт доску уже по новому пространству. Перенос задачи в другой проект (`applyOps.update(doc, { space })`), судя по коду, имеет ту же дыру - на стенде не проверено. Редактор личной доски записать её не может (не член PersonSpace) и не видит; `BoardMiddleware` запрещает смену видимости и пространства всем, кроме автора. `BoardMiddleware.checkPlacement` держит командную доску только в воркспейсе, личную - только в PersonSpace её автора (запрет переноса в чужой PersonSpace - решение пользователя 2026-10-28); передать личную доску другому автору поэтому нельзя без переноса. Владелец воркспейса чужую доску не правит.
- Миграции личных досок в PersonSpace нет (решение пользователя 2026-10-28): доски ещё не выкатывались на публику.
- `dev/tool/src/demoDesign.ts` создаёт доски клиентом их автора (клиент владельца сервер отвергает), личные - в PersonSpace автора.
- Радио дорожек (`RulesTab`): выбранный режим держится в `pending`, пока доска его не покажет. Иначе одна перерисовка со старой доской снимала отметку с нажатой кнопки, а соседнюю браузер уже снял сам - ни одна не отмечена; `bind:group` заменён на `group`. `{#key board}` вокруг радио вешал страницу.
- 2026-10-28: ползунок плотности в шапке и вкладка "Карточка" в настройках спрятаны флагом `tracker-board-next` (решение пользователя); `Board.density` и `Board.cardFields`, заданные раньше, на доске продолжают действовать.
- `boards.spec.ts` и `board-settings.spec.ts` без `test.use({ storageState: PlatformSetting })` открывали браузер без входа (конфиг по умолчанию даёт пустые cookies): в CI первый тест каждого файла видел форму входа, остальные пропускались из-за serial.
- Автопрокрутка канбана при переносе (`autoScrollTick` в `Kanban.svelte`, зона 60px у края) крутит доску, пока курсор стоит у края, даже без движения. Ячейка первой колонки в modern-раскладке начинается в 38px от левого края, поэтому тест, оставивший курсор над ней, сводил на нет `scrollIntoView` к свёрнутой колонке (`kanban.spec.ts` "swim lanes: a card dropped on a stacked column keeps its own lane"); лечится промежуточной точкой в середине доски.
- Правки настроек доски (`BoardEditor` в `boards.ts`): пока есть неподтверждённые правки, эхо с сервера откладывается, иначе эхо правки A стирало правку B. Состояние = последняя серверная версия + очередь неподтверждённых патчей; при ошибке патч выпадает из очереди (откат), остальные остаются. Ошибка показывается через `setPlatformStatus(unknownError(err))`.
- Удалять доску может только автор (`canDeleteBoard`), редакторы - нет.
- `SpaceSecurityMiddleware` проверяет запись по `objectSpace` из транзакции, а Postgres обновляет документ по одному `_id`; поиск доски с правами пользователя прячет чужой приватный `PersonSpace`. Поэтому `BoardMiddleware` читает доски через системный контекст (как `systemContext` в `server-plugins/task/src/middleware.ts`) и отклоняет транзакцию другого класса домена `tracker` с `_id` доски.
- Счётчики статусов в настройках колонок - по запросу `total` на статус, кэш по ключу (проекты + набор статусов): загрузка задач с проекцией ради подсчёта тянула бы все строки проектов.
