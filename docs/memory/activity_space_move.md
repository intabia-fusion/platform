# Activity при переносе документа в другое пространство

- `Activity.svelte` читает сообщения по `{ attachedTo, space: getSpace(object) }`. Сообщения, оставшиеся в старом space, после переноса не видны.
- `TriggersMiddleware.processMove` переносит только объявленные `Collection`-атрибуты класса (у Document это `comments`, `references`). `DocUpdateMessage` (collection `docUpdateMessages`) не объявлен, поэтому оставался в старом space.
- Остальные `ActivityMessage` переносит `getMovedMessagesTxes` в `services/activity/src/activity.ts`, не триггер транзактора. Сервис создаёт сообщения из очереди с отставанием: сообщение для tx до переноса могло появиться в старом space уже после того, как триггер отработал. Сервис обрабатывает tx по порядку, и к tx переноса все прежние сообщения уже записаны. Реакции и ответы на перенесённые сообщения переносит `processMove`, т.к. tx сервиса проходят через транзактор.
- Collaborator (сообщения об изменении `content`) берёт space из свежего документа при сохранении (`server/collaborator/src/storage/platform.ts`), гонки нет.
- Уже перенесённые до фикса документы не чинятся: их сообщения остались в старом space, миграции нет.
- `attribute presenter not found for {"key":"parent"}`: у `Document` был только `ObjectPresenter`, а `getAttributePresenter` ищет `AttributePresenter` класса из `TypeRef`. Добавлен `AttributePresenter` = `DocumentPresenter`. Если ref не читается (родитель в чужом teamspace), `getAttributeValues` отдаёт строку, поэтому `DocumentPresenter` рисует только объект.
- Перенос в корень пишет `parent = document:ids:NoParent`. Его надо считать сбросом значения и в UI (`SetAttributesPresenter.isUnset`), и в тексте уведомления (`services/activity/src/utils.ts`, рядом с `tracker:ids:NoParent`).
- `services/activity` пишет изменение по каждому ключу `operations` без сравнения со старым значением и пропускает только `@Hidden`-атрибуты. Поэтому `moveDocument*` (`plugins/document-resources/src/utils.ts`) передаёт `space` и `parent` только если они изменились.
- Чтобы перенос в другое пространство попадал в историю, `Document.space` больше не `@Hidden`, а `@ReadOnly` с `TypeRef(Teamspace)`, как `Issue.space` в tracker. Значение рисует `SpaceRefPresenter`, `AttributePresenter` у `core.class.Space`. Правая панель атрибутов в `EditDoc` не рендерится (`isCustomAttr={false}`), так что как поле `space` в UI документа не появляется.
- Фразы в ленте и во Входящих собирает `SetAttributesPresenter` из кусков ("{поле} установлен на"). `@Activity({ set, unset })` читает только `services/activity` для `messageIntl` (push/email). Отсюда ошибки рода ("Имя установлен", "Пространство установлен"), это отдельная задача.
