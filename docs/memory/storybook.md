# Storybook (dev/storybook)

- Storybook 9+ требует Svelte 5 (`@storybook/svelte@9/10` peer `svelte: ^5`, `addon-svelte-csf@5` тоже); на Svelte 4 потолок - 8.6. Истории в CSF3 `.ts`, чтобы при переходе на Svelte 5 обновить только Storybook.
- `@storybook/svelte-vite` 8 не добавляет svelte-плагин сам - без `vite.config.mts` с `svelte()` сборка падает на `PreviewRender.svelte (1:0): Expression expected`.
- `lib/` workspace-пакетов (`analytics`, `platform`, `core`) - CommonJS; vite конвертирует CJS только в node_modules ("Analytics is not exported"). Плагин `workspaceSources` (`platform-rig/profiles/ui/vite.mjs`) ведёт bare-импорт на исходники: поле `svelte`, иначе TS-`main`.
- Тип, импортированный как значение в `.svelte`, в vite dev роняет весь модуль (`does not provide an export named`); webpack это глотает. Поиск: `pnpm check:svelte-imports -- --types`.
- `@mdx-js/react` (docs-аддон) просит peer `@types/react` - внесён в `peerDependencyRules.ignoreMissing`, React-типы не нужны.
- `compile_all --lint` (yama `src/build/compile-all.ts`) линтит только пакеты с фазой build; у Storybook её нет, eslint идёт через `_phase:format`.
- Svelte docgen раскрывает алиасы (`IntlString` -> `string & { __id: true; } & ...`); имена возвращает `argTypesEnhancers` `prettifyTypeNames` (`src/helpers/argTypes.ts`) по бренду типа.
- Design-экраны (`src/design`): иконки плагинов регистрирует `src/design/setup.ts` из `plugins/*-assets/src/index.ts` (?raw, разбор `loadMetadata(x.icon, {...})`) и `assets/icons.svg` (?url); строки - `addStringsLoader` на `plugins/*-assets/lang/*.json`. Иконки с переменной спрайта не `icons` (rating-assets: `ratingIcon`) не подхватываются.
- В `build-storybook` малые svg-спрайты инлайнятся в `data:` URL, а `<use href="data:...#id">` браузер блокирует ("Unsafe attempt to load URL"): `assetsInlineLimit: 0` работает только через `viteFinal` в `.storybook/main.ts`, из `vite.config.mts` не применяется.
- Относительный импорт исходников вне `dev/storybook` (чистые иконки task-resources, AvatarInstance, Clock) требует `rootDir: "../.."` в tsconfig, иначе svelte-check ругается на каждый файл ui.
- Markup в Svelte 4 не принимает TS-касты (`x as T`): docgen-плагин падает на `Unexpected token` и указывает на чужой файл (`StoryTheme.svelte`).
- Данные design-экранов: `src/design/demo/demo.generated.json` пишет `node dev/design/generate.mjs demo` (нужен чекаут `../foundation4-demo`).
- Design-кит (`src/design/kit/<Категория>`): визуальные компоненты с доменными пропсами (`kit/types.ts`), без клиента; каталог - `kit/*/<Категория>.stories.ts` (`Kit (pen.dev)/...`). Экраны (истории верхнего уровня с тегом `screen`) (только файлы `design.json` с ключом `storybook`; макеты задач вроде FUSIO-1613 живут только в Penpot/pen.dev) пишет `scripts/generate-screens.mjs` из `dev/design/screens` через записывающий кит `src/design/generated/recorder.ts` (скрипты без правок); список историй статичный, после смены числа фреймов запускать генератор.
- Скрипты экранов зовут `kit.*` Penpot-кита и читают размеры фигур (`main.width`, `content.width`, `board.height`) - записывающий кит обязан отдавать их у слотов; `T(...) + '1A'` теряет токен (остаётся hex, тема тёмная не подхватит).
- Иконки `kit.icon('ns/id')` = id фрагмента спрайта, не имя в metadata: `setup.ts` отдаёт `spriteAssets` ('pkg/fragment' в нижнем регистре -> Asset).
- `hulyComponent` имеет `flex-grow: 1`: боковая панель Workbench без `flex: none` растягивается на всю ширину.
- Холст (`generated/Canvas.svelte`): позиции фреймов запоминает записывающий кит (`kit.Workbench(name, x, y)` пишет `pos`); id истории фрейма для клика по подписи берётся из `index.json` (заголовок + `--frame-N`) и выбирается через `window.__STORYBOOK_ADDONS_CHANNEL__.emit('selectStory')`. Подписи и заголовки страниц лежат вне масштабируемого слоя в экранных координатах (`x * k + tx`): CSS-переменная масштаба внутри слоя пересчитывала стили всех ~12 тыс. узлов, 33 мс на шаг зума против ~1 мс сейчас. Ниже 20% подписи фреймов скрыты, иначе закрывают ряд выше (ряды через 120 px). Слой получает `will-change: transform` только на время движения: при постоянном слое текст после зума мыльный. Кнопки зума тулбара Storybook меняют размер `body` iframe (`width: r*100%`, `transform: scale(1/r)`), поэтому холст `position: fixed; inset: 0`, а не `100vw/100vh`, иначе он занимает часть панели. Холст с одной историей `Canvas` рядом с группами страниц того же префикса в сайдбаре работает. Общий холст всех страниц файла рендерит все кадры сразу и вешает вкладку: он создаётся только для файла с `"canvas": true` в `design.json`, холст страницы - только при двух и более кадрах.

## Настоящие компоненты платформы (истории вложений)

- Storybook рисует настоящие компоненты платформы, Vite строже webpack:
  - `.svelte` собираются с `verbatimModuleSyntax`: `import { Mixin }` без `type` остаётся импортом значения и падает на имени, которого нет. Плагин `typeOnlyImports` (`dev/storybook/vite.config.mts`) выкидывает такие имена по реальным экспортам модуля; кэш списка экспортов ключуется по mtime.
  - Импорты нельзя переписать в чтение из пространства имён: ломаются циклы (`ThemeOptions` в `Theme.svelte`, TDZ). Без `verbatimModuleSyntax` теряются сторы, которые разметка читает как `$store`.
  - У `emojibase` нет default, а `plugins/emoji/src/types.ts` его реэкспортирует: прокладку `src/shims/emojibase.ts` подставляет плагин `emojibase-shim` с `enforce: 'pre'` (перед `workspaceSources`).
  - У `*-assets` в `exports` нет `./src/lang`: строки грузятся `import.meta.glob` из `lang/*.json` (`src/attachments/mock.ts`).
- Список просмотрщиков (`previewTypes`) задаётся в `src/attachments/mock.ts` и держится подпиской: запрос к пустой модели отвечает позже и сбросил бы список.
- Состояние «грузится»: запросы на `/__hang/...` dev-сервер не отвечает никогда (плагин `hangingRequests`), поэтому Playwright открывает такие истории с `waitUntil: 'commit'`. После правки `vite.config.mts` Storybook перезапускается: `kill $(lsof -tiTCP:6006 -sTCP:LISTEN)` (`pkill -f "storybook dev"` процесс не находит).
- Headless Chromium не рисует PDF во фрейме: пустой PDF на скриншоте - не поломка.
- Иконки `view` (`Open`, `Sidebar`) мок ставит по одной `setMetadata` из `view-assets/assets/icons.svg?url`: `loadMetadata` требует все ключи плагина и падает на первом пропущенном.
- Превью ссылки в Storybook - blob-ссылка на JSON (в ней есть `://`, хранилище не нужно); `data:` не подходит.
- `ReferenceError: X is not defined` после нового экспорта из пакета - кэш `typeOnlyImports`: список экспортов `index.ts` хранится по mtime самого `index.ts`, а не файлов за `export *`, и плагин вырезает «неизвестное» имя из импорта. Лечится `touch` индекса пакета и импортирующих `.svelte` (их преобразование vite тоже кэширует) или перезапуском Storybook.
- Вкладки сайдбара (`.storybook/sections.ts`): слот `types.experimental_SIDEBAR_TOP` рисуется в строке шапки между брендом и шестерёнкой, дерево режет `api.experimental_setFilter`. Фильтр сужает и поиск. Менеджер (`.storybook/manager.ts` и всё, что он импортирует) пересобирается только перезапуском `pnpm storybook`; без перезапуска новые истории приходят, а старый код вкладок кладёт их не туда. `storyChanged` на первой загрузке приходит до индекса менеджера: вкладку по ссылке ставят ещё `storyPrepared`/`docsPrepared`. React в пакете нет: разметка через `jsx`/`styled` из `@storybook/theming`.
- Компонент с одной историей, чьё имя совпадает с последним сегментом `title`, Storybook показывает одной строкой без раскрытия: так сделаны страницы Overview (`!autodocs` + `name` = название страницы).
- Превью Storybook прокручивает `body` (`sb-main-padded`), а не окно: `window.scrollY` там всегда 0, держать страницу наверху - через ближайший прокручиваемый предок (`StoryStack.scroller()`). `scrollIntoView` в iframe двигает и блоки менеджера с `overflow: hidden` вокруг него, колесом их не вернуть. `DatePicker` ставит фокус в поле при открытии, и на странице из многих открытых попапов последний уводит её вниз: в историях `autofocus={false}`.
- После очистки `node_modules/.cache/storybook/*/sb-vite` имена чанков меняются при том же `?v=<browserHash>`: браузер берёт старые модули из кеша, и Docs-страницы пустые (в инкогнито работают). Лечится жёсткой перезагрузкой с очисткой кеша.

## Иконки платформы (`src/icons`)

- Svelte-иконки нельзя импортировать глобом всех плагинов (падает vite, см. выше), поэтому `scripts/platform-icons.mjs` достаёт разметку статически: первая ветка `{#if}`, `fill={...}`/`{fill}` -> `currentColor`, прочие выражения и директивы выкидываются, компоненты внутри svg удаляются. id внутри иконок получают префикс: разные файлы используют одинаковые `clip0`, `a`.
- Фоны и диаграммы отсеиваются: `<image>` внутри или больше 64 КБ (login `back.svg` весит 10 МБ).

## Истории плагинов на клиенте в памяти (опрос)

- Истории плагинов (`src/activity`) рисуют настоящие компоненты на клиенте в памяти: `createClient` с самописным `ClientConnection` (`src/activity/client.ts`), модель собрана из tx классов в `model.ts`. `setCurrentAccount` / `setCurrentEmployee` вызываются до `setClient`, документы сотрудников засеваются тоже до него: `onClient` в `contact-resources` перезаливает сторы сотрудников из запроса и затирает заполненное руками.
- `*-assets` грузят иконки через CommonJS `require('…svg')`, vite этого не понимает: плагин `assetRequire` в `vite.config.mts` меняет `require` на `import …?url`. Иконки и строки `*-assets` импортируются относительным путём к `src`: `main` пакета - `lib/`, и `workspaceSources` на исходники его не ведёт.
- Секции с клиентом (`src/attachments`, `src/activity`) делят один документ превью: `setClient` и текущий аккаунт остаются от последней открытой секции, поэтому каждый `setup*` при входе возвращает свои, если они чужие. Плагин платформа загружает один раз на документ, и повторный `addLocation` уже не действует: общий для секций плагин (`emoji`) регистрируется одним `addEmojiLocation` (`src/emoji.ts`) со всеми нужными ресурсами.
- Попап с позицией `'top'` (выбор даты) считает место от `deviceOptionsStore.docHeight`, его пишет корневой `Root` приложения (`packages/ui/src/components/internal/Root.svelte`); без него высота 0 и попап уезжает вверх - в Storybook её выставляет декоратор `StoryTheme`.
