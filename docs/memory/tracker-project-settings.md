# Настройки проекта трекера (FUSIO-1621)

- Workbench находит special по id только среди `navigatorModel.spaces[].specials`; свою страницу без пункта в дереве делает фильтр `projectSettingsId` в `ProjectSpacePresenter`.
- `tracker.actionImpl.*` в tracker-resources не объявлен (только в models/tracker/src/plugin.ts): ресурс через `getResource` оттуда не взять, общий код выносится в модуль (`projectActions.ts`).
- Сброс исполнителя по умолчанию - `$unset: { defaultAssignee: true }`.
- `StatusSelector` ничего не рисует при пустом `value`; проект без статуса хранит `defaultIssueStatus: ''`, поэтому секция подставляет первый статус типа задач.
- Members table: one multiselect role list per member; "owner" entry = `project.owners`, other entries = project type `Role` mixin fields (`rowRoles`/`applyRoles` in `projectSettingsLogic.ts`). The role field is a kit `SelectButton field` opening `ModernPopupLabels` itself; the open popup is fed the stored roles through `popup.update`, so a rejected change snaps it back.
- Rows are kit `SettingRow kind="column"` (added for this page: caption column 13.75rem, hint text under it, no line); fields are kit `SelectButton field` (added: input fill and border instead of a button's, as `DateSelect`), `TextInput`, `TextArea`, widths 10/15/26.25rem set by the section. Our own `SelectField`/`TextField`/`ProjectSettingsRow` were removed as duplicates of the kit after develop got them. `StatusSelector` has no content slot, so `IssuesSection` builds the same status list itself: `taskType.statuses` narrowed to the project workflow's `initialStatuses`.
- Kit `Button` with icon and label is 4px wider than the design kit button: `.button__icon` has `min-width: var(--spacing-2_5)` (1.25rem) even for a 16px icon.
- `SelectButton` with a default slot treats itself as filled: `empty` must be set explicitly, and a value without a person ("Unassigned") goes into the slot too, otherwise the slot renders nothing.
- The project type editor scrolls to a section by `location.fragment` (`SpaceTypeEditor`), section ids are in `models/task/src/index.ts` (`workflows`); a workflow editor is `.../spaceTypes/<type>/workflows/<id>`.
- Create project wizard reuses the settings parts with callbacks instead of writes: `ProjectMembersTable` (members/owners/roles + `onAdd`/`onRemove`/`onRolesChange`, `resetKey`), `ProjectAssigneeSelect`, `ProjectStatusSelect`, `ProjectWorkflowSelect`, `ProjectIconTile`. The wizard saves `members` merged with `owners` (`mergeOwners`), the old dialog could save owners outside members.
- Kit `SettingRow kind="column"` keeps the control at its own width; `fullWidth` (added) lets it take the rest of the row for full-width wizard fields.
- Wizard step body: fixed 28rem with its own `Scroller` (a long members list scrolls inside). A scroller clips the kit focus ring (outline 2px + offset 2px drawn outside the field), so `.step-frame` pads the scroller by 4px and pulls itself out by 4px; without it the ring of a full-width field is cut on the right.
- Create project "based on" (FUSIO-1621): the base is read at choice time with `findAll` (roles of the base type, templates, components, milestones), not by queries: the roles query of the wizard follows `typeId` and would answer after the steps were filled. Toggling a copy group re-applies only that group (`applyBase(group)`), so edits on later steps survive other toggles.
- The default assignee from the base is dropped by a reactive `keepAssignee` while `assigneeFromBase` is set; picking an assignee by hand clears the flag, so an empty project still allows a non-member assignee as before.
- Content copy runs after the project and its mixins are committed, in its own `apply`: a failure leaves the project and shows `MessageBox` (`canSubmit: false` hides Cancel). The wizard's inputs share ids with the settings page (`input#project-title`): scripts and tests must scope to `form[data-id="project-create-wizard"]`.
- Archived spaces are cut by the server `SpaceSecurityMiddleware` unless the query has `showArchived: true` (or a string `_id`/`space`, see `shouldShowArchived` in core `storage.ts`). The wizard's projects query passes it, otherwise archived projects are missing from the base list and their identifiers are not seen as taken. The `notMatch` check of `apply` runs without `showArchived`, so it does not catch an archived duplicate on its own.
