# Пакетная загрузка в десктопе

Область: [Платформа: рабочее место, настройки, экспорт, бэкап, desktop](../features/platform-infra.md)

- Без `setSavePath` Electron на каждый `will-download` показывает окно сохранения, поэтому «Скачать все» по одному файлу открывает N окон.
- `item.setSavePath` работает только синхронно внутри `will-download`. Если вызвать его после `await`, окно всё равно появится.
- Адрес загрузки сверяется по `item.getURLChain()`: после редиректа `getURL()` может не совпасть с тем, что передал renderer. Renderer передаёт абсолютный адрес, полученный через `new URL(..., location.href).href`.
- Загрузки запускает main через `webContents.downloadURL`, а не renderer кликом по ссылке. Так не нужна пауза между файлами и не нужен атрибут `download`, который игнорируется для другого origin.
- Electron перезаписывает существующий файл молча, поэтому имена подбирает main: проверяет диск и имена, ещё не докачанные (`inFlight` на весь модуль, до `done`): пока файл пишется во временный `.crdownload`, диск считает имя свободным, и вторая пачка в ту же папку взяла бы его снова.
- Ожидающая загрузка хранится по адресу: пока она не дошла до `will-download`, тот же адрес не запускается второй раз (дубль в пачке тоже пропускается); не начавшаяся загрузка забывается через минуту (`PENDING_TTL_MS`).
- Занятость имени сверяется без регистра и после NFC (`nameKey`): диски macOS и Windows не различают «Отчёт.pdf» и «отчёт.pdf», а `existsSync` пока файл качается не помогает - оба взяли бы одно имя, и второй затёр бы первый.
- Имя чистится под Windows: управляющие символы, точка или пробел в конце (Windows их отбрасывает, имя на диске разошлось бы с проверенным), `CON`/`NUL`/`COM1`… (по части до первой точки) получают `_`. Длина - до 240 байт, а не 255: рядом пишется `<имя>.crdownload`. Кириллица - 2 байта на букву, это около 120 символов. Слишком длинное или непригодное имя прерывает загрузку, а не сохраняет файл.
- Main не доверяет renderer: `validEntries` пропускает только `http(s)` и строки в `url`/`name`, без белого списка адресов: `getFileUrl` отдаёт внешний адрес вложения как есть, такие файлы скачивались и раньше; `file:` скопировал бы локальный файл в папку. Отклонённые файлы `downloadToFolder` возвращает по именам, окно показывает про них тост (`presentation.string.FilesNotDownloaded`, без строки имён, если имён нет); `SimpleNotification` берётся `import()`-ом: `view-resources` в десктопе грузится лениво.
