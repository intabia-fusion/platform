# Регистрация: клики кнопки и цели Метрики

Область: [Аккаунты и вход](../features/auth-onboarding.md)

- «Попытка» (`signup_click`) ставится в `performAction`, где запрос реально уходит, а «глухое» нажатие (`signup_click_blocked`) — обработчиком на обёртке-строке в фазе **захвата** (`on:click|capture`) в `plugins/login-resources/src/components/Form.svelte`. На всплытии тот же клик приходит уже после старта отправки (`inAction` === true), поэтому мерить оттуда нельзя.
- Различаются цели наличием параметра `reason` (`consents` — не отмечены согласия, `invalid` — кнопка погашена валидацией); отдельного флага `blocked` нет.
- Клики по задизейбленной кнопке доходят до обёртки, а не до кнопки: у `.form-button:disabled` стоит `pointer-events: none`, целью события становится контейнер; нажатие во время отправки (`inAction`) не считается вовсе.
- Имена целей захардкожены в `packages/analytics-providers/src/yandexMetrika.ts` (`signup_click`, `signup_click_blocked`, `signup_submit`), событие-продюсер — `plugins/login-resources/src/analytics.ts` (`signup.submitAttempt`). Литералы живут в двух пакетах, тест ловит только сторону провайдера.
- Цель должна существовать в счётчике **до** релиза: `reachGoal` для незаведённой цели данные не сохраняет и задним числом не восстанавливает. Номер счётчика задаётся в конфиге деплоя (env `YANDEX_METRIKA_ID` у фронта), в репозитории платформы его нет.
- До логина события видит только Яндекс.Метрика: `AnalyticsCollectorProvider` без токена батчи не отправляет (`analyticsCollector.ts`).
- Enter внутри формы отправляет её из любой точки — обработчик `on:keydown` не смотрит на `target`, поэтому Enter на ссылке провайдера регистрирует пользователя вместо перехода.
