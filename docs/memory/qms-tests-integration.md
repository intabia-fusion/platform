## Root-cause quirks

- **Workspace selector substring match.** `tests/sanity/tests/model/select-workspace-page.ts` `workspaceButtonByName`: `sanity-ws-qms` sorts before `sanity-ws` in the workspace list, so a `hasText` substring filter + `.first()` picks the wrong workspace once both exist on one stand. Current code uses an exact match: `filter({ has: page.getByText(workspace, { exact: true }) })`.
- **Person-picker fulltext search.** `qms-tests/sanity/tests/model/common-page.ts` `selectListItemWithSearch`: the contact-resources person popup searches fulltext (`$search`) over `Person.name`, stored as `"last,first"` (e.g. "Appleseed,John"); typing the displayed "Last First" order returns an empty list. Selection clicks the `list-item` by `hasText` directly instead of typing into the search box (list is short, 3-5 people).
- **Comment-flow overlay.** The floating comment popup leaves a `div.modal-overlay` that intercepts later clicks; Escape does not dismiss it reliably. `closeNewMessagePopup` (`document-content-page.ts`) presses Escape in a loop until the overlay element *count* is 0 (not visibility, to avoid the fade race); `completeReview` and `openComments` use `dispatchEvent('click')` to bypass a still-present overlay.
- **Non-exact `getByRole` names.** Space/folder names come from `faker.word.words(1)` and can be 1-2 letters ("a", "or"); `getByRole('button', { name })` matches substrings, so strict mode hits every nav item containing them. Space/folder locators in `document-content-page.ts` and `filter` use `exact: true`.
- **Stale app before `clickOnTeamspaceOrArrow`.** After `clickDocumentsSpace` the Controlled Documents "New document" split arrow (`.w-full > button:nth-child(2)`) is still on screen, so an instant `isVisible` check clicked it and opened the wrong wizard. It now waits for the `/document` URL first.
- **Multi-select popup close.** `setReasonAndImpactData` closes the impacted-documents popup with Escape + `toBeHidden`; a forced click on the tab sometimes left it open.
- **TESTS-388 is one-shot per stand.** It kicks user4 from the workspace; rerunning ES-40 on the same stand fails at user4 login ("Select workspace" with no workspaces). Recreate the stand.
- **Member-button locator.** `document-content-page.ts` `clickMembersButton()` matches the button by the `/\d+ members?$/` suffix regex - the initials shown before the count vary with the member set.
- **Reason & Impact one-way binding (product bug).** `plugins/controlled-documents-resources/src/components/document/EditDocReasonAndImpact.svelte`: a live `ccQuery` update while the user is typing used to reset the field to the stored value (one-way `bind:value`), and a later blur then persisted the stale value. Fixed with local `description`/`reason`/`impact` copies plus a `focusedField` guard - `ccQuery` syncs a field only when it is not the currently focused one.

## test.slow()

Default Playwright timeout is 60s; `test.slow()` triples it (180s) and overrides a lower CLI `--timeout`. Used by TESTS-140 (comments/compare, `documents.spec.ts`), TESTS-325 (REQ-03, versions), TESTS-399 (REQ-04) - not by TESTS-136/139/206, which only look similar. `checkComparingTextAdded`/`checkComparingTextDeleted` separately use `toBeVisible({ timeout: 30000 })`, since diff highlights render after the compare view loads.
