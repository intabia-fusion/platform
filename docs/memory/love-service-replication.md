# love service: реплицируется

`services/love` может работать в нескольких репликах за балансировщиком. Отсюда правила:

- **Никакого process-local планирования.** Webhook от LiveKit приходит на произвольную
  реплику, следующий webhook по той же комнате - на другую. `setTimeout` + `Map` в памяти
  процесса (отложенное закрытие, отмена по `room_finished`) ломается: отменять некому,
  а при рестарте реплики таймер теряется совсем.
- **Общее состояние - это LiveKit.** `listRooms` / `listParticipants` видят все реплики
  одинаково. Решение, выведенное из свежего чтения LiveKit, любая реплика примет одно и то же,
  а параллельный `deleteRoom` идемпотентен.
- **Метки времени - в metadata комнаты LiveKit.** `updateMetadata` (`utils.ts`) читает блоб
  и мержит, потому что `updateRoomMetadata` заменяет его целиком. Так у всех реплик одни часы.
- **Периодические решения живут в `polling.ts`.** Цикл крутится в каждой реплике и уже читает
  LiveKit по всем комнатам. Реплика, поднявшаяся позже, закроет комнату позже - fail-open.

- **Любое завершение митинга приходит дважды.** `room_finished` webhook и polling
  (`cleanupStaleRoomStates`) оба зовут `finishMeeting`, а при N репликах - N+1 раз. Поэтому
  `finishMeeting` не трогает уже `Finished` митинг, а удаление knock-инвайтов по комнате
  пропускается, если в комнате уже живёт другой митинг (разбор - `sanity-flaky-tests.md`, 2026-09-15).
- **Инвайт-knock несёт только комнату**, поэтому «чья это заявка» решается по времени: удаляются
  только те, что созданы до конца митинга (`meetingEnd`, а не `now` - завершений несколько).
  Вопрос «а не идёт ли в комнате другой митинг» - это чтение перед удалением, и митинг,
  стартовавший между ними, терял свои knock-и.
- **Ни один обработчик очереди не должен бросать на housekeeping.** Consumer повторяет упавшее
  сообщение в `while (true)`, партиция общая для всей группы, то есть для всех реплик. Одно
  «вечно падающее» сообщение затыкает обработку вебхуков целиком (разбор - `sanity-flaky-tests.md`,
  серия 15:11-17:40 2026-09-15). `updateMetadata` поэтому не бросает.
- **Взаимное исключение - в транзакторе, не в Map.** `TxApplyIf` со `scope` + `notMatch`
  (`ApplyTxMiddleware`) - проверка и запись атомарны для всех реплик. Так резервируется запись.

Так сделан D7 (F5 владельца офиса не должен завершать митинг): webhook ставит `ownerLeftAt`,
`closeRoomIfOwnerGone` в polling закрывает комнату, если штамп пережил grace, и снимает его,
если владелец вернулся. Первый вариант с `setTimeout` в webhook отвалился именно на репликах.
