# Чат: права на правку и удаление сообщений на сервере

Область: [Чат](../features/chat.md).

- Каналы и директы - не `TypedSpace`, поэтому `SpacePermissionsMiddleware` их пропускает, а `SpaceSecurityMiddleware` проверяет только участие в пространстве. До `ChunterMiddleware.onMessageChange` любой участник мог подделанной tx удалить или переписать чужое сообщение. В интерфейсе это закрывал только `canDeleteMessage`.
- Правило "правит только автор" нельзя применять ко всем полям. У наследников `ChatMessage` другие участники законно меняют свои поля: закрепление `isPinned`, `resolved` у комментариев документов, `applied`/`subtasks`/`project` у предложений AI. Поэтому только автору разрешены поля содержимого и привязки (`authorMessageFields`), а `createdBy`/`createdOn` не меняет никто, иначе можно переписать автора и пройти проверку.
- Tx под базовым классом (`ActivityMessage`) или любым другим классом домена `activity` хранилище пишет в ту же строку по `_id`. Поэтому правило ловит tx по домену, а решает по классу сохранённого документа. Документ берётся через `lowLevelStorage.rawFindAll`: `findAll` middleware фильтруется пространствами сессии, и сообщение из закрытого для отправителя канала не нашлось бы, а запись по `_id` всё равно прошла бы.
- `space` и счётчик `applets` - тоже поля автора: перенос в свой канал уносит чужое сообщение вместе с опросами, `applets: 0` прячет опрос из inbox, поиска и тредов.
- Но `space` чужих комментариев законно меняют клиенты: `moveIssueToSpace` (tracker) и общий `moveToSpace` (view, кандидаты, карточки) одной apply-пачкой переписывают `space` всех элементов коллекций, вплоть до ответов и опросов. Поэтому апдейт из одного `space` разрешён, если в той же пачке родитель (`attachedTo`) переезжает туда же (`followsParent`). Родитель сверяется по таблице: апдейт того же `_id` под классом другого домена ничего не переносит. Сообщение канала или директа (родитель - пространство) так не переезжает.
- Поля апдейта собираются и из операторов (`getUpdatedFields`): `$unset: { message }` и `$rename: { x: 'message' }` меняют текст так же, как `message: ...`. `TxMixin` с `mixin`, который не класс-миксин, адаптер пишет как `doc[mixin] = ...`, поэтому такой mixin запрещён.
- Каскад удаления сообщения (ответы треда, реакции, вложения, опросы) приходит через `context.derived` с `isTriggerCtx`. Его правило не проверяет: автор родителя удаляет и чужие ответы. Актор - `ctx.contextData.account`, а не `modifiedBy` производной tx.
