# Чат: права на правку и удаление сообщений на сервере

Область: [Чат](../features/chat.md).

- Каналы и директы - не `TypedSpace`, поэтому `SpacePermissionsMiddleware` их пропускает, а `SpaceSecurityMiddleware` проверяет только участие в пространстве. Чужое сообщение от подделанной tx защищает только `ChunterMiddleware.onMessageChange`; `canDeleteMessage` в интерфейсе лишь прячет действие.
- Не автору разрешён короткий список полей (`isPinned`, `resolved`), а не наоборот: новое поле у сообщения или наследника по умолчанию авторское. `createdBy`/`createdOn` не меняет никто, иначе можно переписать автора и пройти проверку.
- Законные правки чужих сообщений вне этого списка. Карточки-предложения бота ИИ меняет любой, кто их видит, вплоть до `message` (Create дописывает ссылки на задачи, `TaskProposalPresenter.svelte`), поэтому эти классы из правила исключены. Объединение персон (`MergePersons`, только Maintainer+) переписывает ссылки сообщений на объединяемую персону, поэтому Maintainer+ правилу автора не подчиняется.
- Tx под базовым классом (`ActivityMessage`) или любым другим классом домена `activity` хранилище пишет в ту же строку по `_id`. Поэтому правило ловит tx по домену, а решает по классу сохранённого документа. Документ берётся через `lowLevelStorage.rawFindAll`: `findAll` middleware фильтруется пространствами сессии, и сообщение из закрытого для отправителя канала не нашлось бы, а запись по `_id` всё равно прошла бы.
- `space` и счётчик `applets` авторские не случайно: перенос в свой канал уносит чужое сообщение вместе с опросами, `applets: 0` прячет опрос из тредов, сохранённых и закреплённых.
- Но `space` чужих комментариев законно меняют клиенты: `moveIssueToSpace` (tracker) и общий `moveToSpace` (view, кандидаты, карточки) одной apply-пачкой переписывают `space` всех элементов коллекций, вплоть до ответов и опросов. Поэтому апдейт из одного `space` разрешён, если в той же пачке родитель (`attachedTo`) переезжает туда же (`followsParent`). Родитель сверяется по домену: апдейт того же `_id` под классом другого домена ничего не переносит. Сообщение канала или директа (родитель - пространство) так не переезжает.
- Поля апдейта собираются и из операторов (`getUpdatedFields`): `$unset: { message }` и `$rename: { x: 'message' }` меняют текст так же, как `message: ...`. `TxMixin` с `mixin`, который не класс-миксин, адаптер пишет как `doc[mixin] = ...`, поэтому такой mixin запрещён.
- Каскад удаления сообщения (ответы треда, реакции, вложения, опросы) приходит через `context.derived` с `isTriggerCtx`, и правило его не проверяет: автор родителя удаляет и чужие ответы. Актор - `ctx.contextData.account`, а не `modifiedBy` производной tx.
- Отказы: правка и удаление чужого - `ForbiddenKind.AuthorOnly`, смена авторства и чужой mixin - `SystemOnly`. Своего текста у `AuthorOnly` нет, клиент пишет общее "Нет доступа".
