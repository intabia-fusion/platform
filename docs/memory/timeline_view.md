# Timeline view (FUSIO-1448)

Generic Gantt-like viewlet `view.viewlet.Timeline` -> `plugins/view-resources/src/components/TimelineView.svelte` on top of `packages/ui/src/components/Timeline.svelte`. Consumers: milestones page (`MilestoneTimeline`), issues view (`IssueTimeline`), milestone panel (`MilestoneIssuesTimeline`, `EditMilestone.svelte`).

- **Postgres adapter has no `$or`.** A top-level `$or` is treated as a data field (`data#>>'{$or}' = ARRAY['[object Object]']`, error `operator does not exist: text = text[]`). The windowed query is split into several live queries (`windowConditions`) merged on the client.
- **Mixin fields in queries** use the key `<mixin>.<attr>` (e.g. `task:mixin:TimeManaged.startDate`); range operators work on them. Writes go through `updateMixin`, reads through `hierarchy.as`.
- **Svelte reactive loop:** a `$:` block depends on every variable read anywhere inside it, callbacks included. A query callback that read its own results array re-ran the block and froze the app. Subscriptions live in a plain function (`subscribe`) called from the reactive block.
- **Alignment:** the global `.listGrid` class adds `padding-left: 12px`; `Timeline.svelte` resets it, otherwise bars drift half a day off the header and background layers. `.headerWrapper` needs `box-sizing: border-box` for the same reason.
- **Dates:** `TimeManaged` mixin on `task.class.Task` holds only `startDate`; the end is `dueDate` (a separate `endDate` was dropped as a duplicate of it). No start: the bar ends at `dueDate` and lasts `estimation` hours in 8-hour work days (`TimelineField.estimation`, `estimatedStart`); any drag of such a bar writes the start. Server trigger `OnStateUpdate` (`server-plugins/task-resources`) fills `startDate` on entering `Active`, only when empty.
- **Window:** `timelineMonthStore` / `timelineRangeStore` (`plugins/view-resources/src/timeline.ts`, persisted in localStorage). Data is loaded for at least 3 months, the selected range is highlighted by tinting everything outside it. `dayWidth` per range: 24/10/5/2.5 px.
- **Duplicate ids in `mergeIds`:** a key added to `plugins/view/src/index.ts` that already exists in `view-resources/src/plugin.ts` (e.g. `string.NotSpecified`) passes tsc, lint and svelte-check, but throws `'identify' overwrites 'NotSpecified' for view:string` at runtime and the workbench does not load. Only the browser shows it.
- **No view settings for Timeline:** `ViewletSettingButton` hides the configure button for `view.viewlet.Timeline`, and `TimelineView` ignores the preference `config`. A stored preference config drops the model keys, so milestone names were replaced by the toggled attribute.
- **ObjectPopup** renders nothing without an `item` slot or `type: 'presenter'`; opening it via `showPopup` without a slot gives empty rows.
- **Pure logic lives in TS modules with tests:** `packages/ui/src/timelineMath.ts` (day offsets via `setDate`/`Math.round`, safe across DST; tests run with `TZ=Europe/Berlin`), `plugins/view-resources/src/timelineRows.ts` (window, lanes, rank-drop neighbours by parent/group, window result collector), `plugins/tracker-resources/src/milestoneUtils.ts` (work hours, schedule, stats; no `@hcengineering/ui` import so jest loads it), `server-plugins/task-resources/src/timeManaged.ts` (trigger decision; end before a future start pulls the start back). Svelte reactivity and document listeners are not unit-testable here.
- **`$in` with `null`** is supported by the postgres adapter (`= ANY(...) OR IS NULL`), so `milestone: { $in: [id, null] }` works server side.
- **Drag between rows:** only the left-panel handle is `draggable` (the row stays clickable); `Timeline` finds the row under a moving bar via `document.elementFromPoint` + `data-row`, only rows with `TimelineRow.droppable` (resource rows) count. `Timeline.test.ts` has a pre-existing splitter test that breaks `Element.prototype.getBoundingClientRect` for tests after it: new tests go before it.
- **LiveQuery and mixin filters:** a query on the base class filtering by `<mixin>.<attr>` (the windowed issue timeline) did not pick up a doc outside its results when only a `TxMixin` arrived - dates set in the issue panel did not bring the issue onto an open (or cached) timeline. `txMixin` in `foundations/core/packages/query` now re-checks such docs with `findOne`.
