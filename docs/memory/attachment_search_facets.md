# Поиск вложений: фасеты и привязка к чату

Область: [Чат](../features/chat.md)

## Индекс
- Фасеты (`IndexedDoc.facets`, keyword) считает при индексации `SearchPresenter.facets` класса. Новый фасет или правка классификации (`getAttachmentCategory`) появится в индексе только после переиндексации - миграция `attachment-search-reindex-v1` (models/chunter/src/migration.ts) переиндексирует `Attachment` (`DOMAIN_ATTACHMENT`) и `ChatMessage` (`DOMAIN_ACTIVITY`). Свойство `facets` в общий индекс добавляет `putMapping`, индекс не пересоздаётся (см. [fulltext_search_fields.md](fulltext_search_fields.md)).
- Провайдер фасетов, который не загрузился или упал, только пишет ошибку: иначе падала бы вся пачка индексации.
- Провайдер получает весь пакет индексации (`batch`): превью ссылок всех сообщений пакета грузятся одним запросом.
- Вложения создаются при отправке, отдельными транзакциями перед сообщением (`attachedTo` - id сообщения). Индексатор может увидеть их раньше сообщения: такое вложение индексируется без фасетов и без текста файла (`draft` в `indexDocuments`). `processTransactions` при создании сообщения переиндексирует его вложения (`indexMessageAttachments`) - тогда и фасеты, и текст файла, извлечение одно.
- Вложения без документа удаляет `remove-orphan-attachments-v1` (`models/attachment`), см. [drive-media.md](../features/drive-media.md). Она идёт в миграциях вложений, раньше love, documents и других, которые переносят родителей между доменами: на воркспейсе, где те ещё не прошли (заброшенный, старый бэкап), живые вложения сойдут за «сирот». Удаление сообщения каскадом убирает его вложения, висящих от него нет.
- `reindex(domain, classes)` индексирует только названные классы: `DOMAIN_ACTIVITY` с `[ChatMessage]` не гоняет остальную активность, а наследников (`ThreadMessage`, голосовые) нужно перечислять самому - `getDescendants`.
- Вложение сообщения индексируется с `rootObject` чата сообщения: иначе не работали бы фильтр «Где» и плашка чата. Вложение, чьего сообщения уже нет, индексируется как черновик: без фасетов и текста файла, а `rootObject` в индексе - само сообщение, не чат. Вкладки браузера такое вложение не показывают.
- Превью ссылки - тоже `Attachment` (`type = LINK_PREVIEW_TYPE`) вида `link`, в медиа и файлы не попадает. На вкладке ссылок ищутся сами сообщения (фасет `message-link`): адреса и тексты превью `ChatMessageSearchFacets` отдаёт в `SearchFacets.extra`, индексатор дописывает их в `fulltextExtra` сообщения, по нему идёт поиск `extra`.
- Обрезка пунктуации в конце голого адреса (`trimBareUrl`, text-core) - проход по строке, не регэксп: `[...]+$` на длинной серии точек внутри адреса квадратичен, а `extractLinks` работает и в индексаторе, и в каждой карточке ссылки.
- Лента без запроса - `searchFulltext` с `allowEmptyQuery: true` (`SearchQuery`): пустой `query` -> `match_all`, решают только фильтры; набранный текст ищется как обычно, поэтому браузер передаёт флаг всегда. Пустой `query` без флага по-прежнему ничего не находит: им пользуются другие поиски, например `SearchObjectPopup` при пустом поле; сортировка `relevance` без запроса бессмысленна, клиент подменяет её на дату (`shownOrder`, `search/browser.ts`; запрос всегда несёт итоговый порядок).

## Отображение
- Нет страницы от сервиса превью - карточка показывает значок формата. Страница запрашивается в пропорции A4 с `fit=cover` (иначе сервис обрезал бы середину листа), карточка показывает её верх.
- Постер видео - `hls.thumbnail` из полей вложения (или `metadata.hls.thumbnail`). Нет постера или он не загрузился - плитка показывает заглушку с кнопкой воспроизведения.
- Иконки и обложки сайтов (`SiteIcon`, `SiteTile`) грузятся с самих сайтов (`/favicon.ico`, `/apple-touch-icon.png`); неудачный адрес запоминается на сессию.
- Плитка медиа без фона: скриншоты macOS несут прозрачную тень по краям, через неё просвечивал бы фон темы.
- Скелетон вкладок держит место строки счётчика `padding`, а не `margin`: margin схлопывается с отступом месяца, и список при загрузке прыгает на 8px.
- Просмотрщик вложений (`showAttachmentPreviewPopup`: `fullSize` и `fullWindow`) в браузере перекрывает статус-бар, а в десктопе встаёт под него: там статус-бар - заголовок окна (`desktopPlatform`, `PopupInstance.svelte`). Попап с одним `fullSize` статус-бар не перекрывает.
- Клик по сообщению из «Сохранённых», «Тредов» и поиска (`openMessageFromSpecial` -> `openSearchResult`, `navigation.ts`) открывает задачу или документ в чате их панелью, как навигатор, и прокручивает активность к сообщению. Недоступный объект - клик без реакции, такого случая быть не должно, чинить не нужно.
