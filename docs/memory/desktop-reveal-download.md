# Показать загрузку в папке

Область: [Платформа: рабочее место, настройки, экспорт, бэкап, desktop](../features/platform-infra.md)

- Renderer называет загрузку только по `key`: main держит `Map<key, savePath>`, которую наполняет `handleWillDownload` на `done` со статусом `completed` (`rememberDownload`). Путь из renderer не принимается вообще, поэтому `window.electron` не может открыть произвольный файл и не работает оракулом существования файлов (`desktop/src/main/revealDownload.ts`).
- Статусы: `ok`, `missing` (файл удалён/перемещён после загрузки), `failed` (ошибка открытия файла/папки или IPC; причина не обязательно связана с ассоциацией файлов), `cancelled` (пользователь отказался в подтверждении), `unknown` (id этой сессии main не завершал; renderer показывает его как `missing`), `unavailable` (нет моста - запуск вне десктопа).
- `failed` значит «файл на месте, ОС не смогла открыть», поэтому в попапе у такой строки остаётся «Показать в папке» и скрывается только «Открыть файл»; при `missing`/`unknown` скрыты обе.
- `shell.showItemInFolder` синхронный, ничего не возвращает и об ошибке не сообщает, поэтому `missing` определяется заранее через `fs.existsSync`. На Linux выделение идёт через DBus `org.freedesktop.FileManager1.ShowItems`; без сессионной шины (`DBUS_SESSION_BUS_ADDRESS` пуст) вызов - тихий no-op, поэтому там открывается сама папка (`shell.openPath(path.dirname)`). Main ожидает результат и возвращает `failed` при ошибке.
- Открытие одним кликом разрешено только для безопасных типов: белый список `SAFE_EXTENSIONS` в `desktop/src/main/downloadFileTypes.ts` (`isSafeToOpen`). Чёрный список исполняемых отстаёт от реальности, белый - нет: неизвестный или новый тип (`.url`, `.wsf`, `.application`, `docm`) попадает в подтверждение. `svg`/`html` в белом списке нет (скриптуемые), `docm`/`xlsm`/`pptm` и OpenDocument (`odt`/`ods`/`odp`) - из-за макросов.
- Подтверждение живёт в main (`dialog.showMessageBox`, кнопки «Открыть»/«Отмена», `defaultId`/`cancelId` = Отмена), а не в попапе: код страницы может позвать `openDownloadItem(key)` напрямую, и проверка типа в renderer это не остановило бы. Тексты диалога переводит renderer и передаёт при вызове - нативный диалог локаль не читает. Это защита от мисклика, а не граница безопасности: при `nodeIntegration: true` код страницы и так может запускать процессы.
- Electron 44.7.0 использует Chromium 152.0.7977.130 ([DEPS](https://github.com/electron/electron/blob/v44.7.0/DEPS)). В [ElectronDownloadManagerDelegate](https://github.com/electron/electron/blob/v44.7.0/shell/browser/electron_download_manager_delegate.h) нет переопределения `GetQuarantineConnectionCallback`; [Chromium по умолчанию возвращает NullCallback](https://github.com/chromium/chromium/blob/152.0.7977.130/content/public/browser/download_manager_delegate.cc). Без подключения quarantine service [BaseFile::AnnotateWithSourceInformation](https://github.com/chromium/chromium/blob/152.0.7977.130/components/download/internal/common/base_file.cc) на Windows вызывает `SetInternetZoneIdentifierDirectly`, а на остальных платформах возвращает `ANNOTATION_FAILED`, не прерывая загрузку. Это подтверждает путь создания `Zone.Identifier`, но не доказывает конкретный результат SmartScreen или защищенного просмотра Office.
- На macOS [Chromium quarantine_mac.mm](https://github.com/chromium/chromium/blob/152.0.7977.130/components/services/quarantine/quarantine_mac.mm) рассчитывает на автоматический карантин ОС через `LSFileQuarantineEnabled` и лишь дополняет существующие свойства. По [документации Apple](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/LaunchServicesKeys.html), значение `true` включает карантин всех создаваемых приложением файлов; значение по умолчанию - `false`. `desktop-package/package.json` задает ключ через `build.mac.extendInfo`. Проверено на локальной macOS-сборке Electron 44.7.0: в `Info.plist` ключ равен `true`, загрузка через `downloadURL` и `setSavePath` получает `com.apple.quarantine` со значением `0081;<timestamp>;Platform;`. У исходного Electron без ключа эта же загрузка метки не имела.
- `shell.openPath` возвращает строку ошибки (`''` при успехе) - единственный из двух вызовов с результатом; отсюда `failed`.
- Мост держит `desktop/src/ui/index.ts` (`setDownloadItemActions`, как `setDownloadFilesHandler`), плагин зовёт `revealDownloadItem`/`openDownloadItem` из `@hcengineering/desktop-downloads` и про `window.electron` не знает.
