# Показать загрузку в папке

Область: [Платформа: рабочее место, настройки, экспорт, бэкап, desktop](../features/platform-infra.md)

- Renderer называет загрузку только по `key`: main держит `Map<key, savePath>`, которую наполняет `handleWillDownload` на `done` со статусом `completed` (`rememberDownload`). Путь из renderer не принимается вообще, поэтому `window.electron` не может открыть произвольный файл и не работает оракулом существования файлов (`desktop/src/main/revealDownload.ts`).
- Статусы: `ok`, `missing` (файл удалён/перемещён после загрузки), `failed` (ОС не смогла открыть - нет ассоциации), `cancelled` (пользователь отказался в подтверждении), `unknown` (id этой сессии main не завершал; renderer показывает его как `missing`), `unavailable` (нет моста - запуск вне десктопа).
- `failed` значит «файл на месте, ОС не смогла открыть», поэтому в попапе у такой строки остаётся «Показать в папке» и скрывается только «Открыть файл»; при `missing`/`unknown` скрыты обе.
- `shell.showItemInFolder` синхронный, ничего не возвращает и об ошибке не сообщает, поэтому `missing` определяется заранее через `fs.existsSync`. На Linux выделение идёт через DBus `org.freedesktop.FileManager1.ShowItems`; без сессионной шины (`DBUS_SESSION_BUS_ADDRESS` пуст) вызов - тихий no-op, поэтому там открывается сама папка (`shell.openPath(path.dirname)`).
- Открытие одним кликом разрешено только для безопасных типов: белый список `SAFE_EXTENSIONS` в `desktop/src/main/downloadFileTypes.ts` (`isSafeToOpen`). Чёрный список исполняемых отстаёт от реальности, белый - нет: неизвестный или новый тип (`.url`, `.wsf`, `.application`, `docm`) попадает в подтверждение. `svg`/`html` в белом списке нет (скриптуемые), `docm`/`xlsm`/`pptm` - из-за макросов.
- Подтверждение живёт в main (`dialog.showMessageBox`, кнопки «Открыть»/«Отмена», `defaultId`/`cancelId` = Отмена), а не в попапе: код страницы может позвать `openDownloadItem(key)` напрямую, и проверка типа в renderer это не остановило бы. Тексты диалога переводит renderer и передаёт при вызове - нативный диалог локаль не читает. Это защита от мисклика, а не граница безопасности: при `nodeIntegration: true` код страницы и так может запускать процессы.
- Метку «скачано из сети» ставит сам Electron (Chromium), дописывать её не нужно: проверено на Electron 44 с `setSavePath` - файл получает поток `:Zone.Identifier` с `[ZoneTransfer] ZoneId=3` и `HostUrl=<адрес>`, поэтому SmartScreen и защищённый просмотр Office срабатывают при `shell.openPath`. На macOS ожидается `com.apple.quarantine` тем же кодом Chromium (`download_file_impl.cc` -> `QuarantineFile`), проверять `xattr -l <файл>`; на Linux метки нет, но скачанные файлы не получают бит исполнения.
- `shell.openPath` возвращает строку ошибки (`''` при успехе) - единственный из двух вызовов с результатом; отсюда `failed`.
- Мост держит `desktop/src/ui/index.ts` (`setDownloadItemActions`, как `setDownloadFilesHandler`), плагин зовёт `revealDownloadItem`/`openDownloadItem` из `@hcengineering/desktop-downloads` и про `window.electron` не знает.
