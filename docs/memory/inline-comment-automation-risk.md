# Автоматизация inline-комментариев на стенде: риск испортить документ вслепую

При подготовке скриншотов для `communication/inline-comments` (FUSIO-1594 фаза 2) попытка
кликнуть по значку комментария на плавающей панели инструментов (`textEditor.icon.Comment`,
последний значок в тулбаре, рядом со значками форматирования) по заранее вычисленным пиксельным
координатам привела к тому, что клик промахнулся (в тот момент тулбар для данного выделения не
показывал значок комментария - он появляется не на любом выделении, зависит от типа блока), а
следующий `page.keyboard.type(...)` ушёл прямо в документ и заменил текст выделенной строки.
Аварийная правка через `Backspace`/повторный набор текста усугубила порчу (слияние строк,
лишние пустые буллеты, опечатка) и была заблокирована классификатором Claude Code
("Modify Shared Resources") на попытке повторной правки.

Документ "Глоссарий" в `demo-ws` (ru, sanity-стенд 8083) остался в испорченном состоянии:
строка "Этап (Milestone)..." слита с "Регресси[я] - ранее исправленная ошибка..." (без последней
буквы "я"), и после неё два лишних пустых буллета перед "Хотфикс". Нужно поправить вручную в UI:
разбить строку на два исходных буллета ("Этап (Milestone) - группа задач, привязанная к
конкретному релизу." / "Регрессия - ранее исправленная ошибка, которая проявилась снова после
изменений.") и удалить два пустых буллета.

Для следующего раза: прежде чем кликать по иконке в плавающем тулбаре редактора (comment, note,
table-actions - всё, что открывает попап), сначала **скриншотом подтвердить**, что иконка в
ожидаемой позиции и тулбар не закрылся/не сместился после предыдущего действия, и только потом
кликать - затем **снова скриншотом** подтвердить, что открылся именно попап с полем ввода (а не
пустой `tippy-box`), и только тогда печатать текст. Если после клика видимого попапа нет -
останавливаться и не печатать ничего, а не пытаться "поправить" уже напечатанным текстом.

Второй, более аккуратный заход (с проверкой позиции значка через crop скриншота и клик по
вычисленным координатам, уже без угадывания) на документе "Чек-лист перед релизом" клик нашёл и
активировал правильную иконку (она становится чёрной/активной, `isActive: {name: 'inlineComment'}`),
но сам попап с полем ввода всё равно не отрисовался (`tippy-box` в DOM есть, `comment-thread`/
`comment-input` - нет) - непонятно, баг конкретно в синтетическом клике Playwright (возможная
гонка с `requestAnimationFrame`/Svelte-тиком, который обычный клик мышью не триггерит так же) или
в самой фиче на этом типе блока. Текст в документ в этот раз не ушёл (ничего не печаталось после
непонятного результата) - страница `inline-comments.mdx` в итоге написана и снята по коду и по
скриншоту одного выделения с тулбаром, без живого скриншота открытого попапа комментария.
