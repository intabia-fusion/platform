# Клик по персоне -> DM

- @-упоминание в тексте сообщения рендерит `ObjectNode` (packages/presentation), который раньше звал `view.component.ObjectMention` напрямую и обходил `PersonElement` с логикой `canOpenDirect` -> клик открывал карточку персоны. Теперь Person-документы идут через `contact.component.EmployeePresenter` inline.
- `highlight`/`transparent` для упоминаний персон прокинуты цепочкой EmployeePresenter -> PersonPresenter -> PersonContent -> PersonElement -> ObjectMention.
- view-resources и presentation не зависят от chunter, поэтому логику DM нельзя положить в `ObjectMention`; она живёт в `PersonElement` через `chunter.function.OpenDirectForPerson` + `hasResource`.
- Кнопки тултипа (`contact.extension.EmployeePopupActions`: DM от chunter, звонок от love) переиспользуются в заголовке карточки персоны: `PersonHeaderActions` на `view.extensions.EditDocTitleExtension`.
- `openDirectForPerson` молча выходил: у документа класса `Person` поля миксина лежат под ключом `contact:mixin:Employee`, `(person as Employee).active` = undefined. Читать только через `hierarchy.as(person, contact.mixin.Employee).active`.
- Ссылки на персону (`PersonElement` type `link`, напр. "Добавил(а) X" в системных сообщениях) открывают DM только внутри chunter (в inbox - карточку). Флаг - module-level `derived(location)` в `PersonElement`: одна подписка на все ссылки, примитив не будит их на каждой навигации.
- Звонок из шапки DM: `chunter.extensions.DirectHeaderExtension` -> `love.component.InviteEmployeeButton` (`sendInvites`, как в офисе). Запрет звонка AI-боту - внутри кнопки (`$aiBotPerson`), не в ChannelHeader. Проверка членства через `getWorkspaceMembers` (FUSIO-634) убрана: кэш на весь клиент отставал от вступивших; критерий теперь Employee + `active === true`, иначе кнопка disabled.
- URL канала/директа `<slug>-<id>`: декодер отличает `ChunterSpace` по отсутствию `|` в `path[3]` (`decodeChatURI`), спецстраницы (`threads`/`saved`/...) проверяются раньше. `LinkIdProvider` зарегистрирован и на `ChunterSpace` - иначе `parseLinkId` для класс-less ссылки не найдёт декодер (он ищет точный класс или предка провайдера). `parseChunterSpaceLinkId` сначала берёт 24-hex хвост (slug вида `my-space-<id>` тоже подходит под модельный шаблон), затем `<plugin>-space-<Name>` -> `<plugin>:space:<Name>`, иначе id как есть. `LinkIdProvider` и категория поиска - модель: без апгрейда модели сервера ссылки остаются голым `<id>`, `@` каналы не показывает.
- В клиентском `@hcengineering/view` нет `string.CopyLink`/`icon.CopyLink` (только в model-view) - в UI берём `chunter.string.CopyLink`/`chunter.icon.Copy`.
- Slug в URL содержит имена участников DM; `navigate` отдаёт в `Analytics.navigate` URL через `stripLinkSlugs` (`<slug>-<24hex>` -> `<24hex>`). Yandex Metrika `/workbench` не трекает вовсе, имена уходили только в `analyticsCollector`.
