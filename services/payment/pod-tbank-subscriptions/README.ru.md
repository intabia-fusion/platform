# Сервис подписок Т-Банка (`pod-tbank-subscriptions`)

## Обзор

Сервис управляет полным жизненным циклом рекуррентных платежей Т-Банка (Тинькофф) для платформы Foundation. Выступает посредником между платёжным провайдером (`pod-payment`) и API Т-Банка.

## Как это работает

### Поток создания подписки

1. **Пользователь выбирает тариф** на странице биллинга → `pod-payment` получает запрос `createSubscription`
2. **`pod-payment` делегирует** запрос в этот сервис через HTTP (`POST /api/v1/subscriptions`)
3. **Инициируется платёж** через `tbank.initPayment()` с флагом `Recurrent: 'Y'` (разрешает повторные списания)
4. **Pending-подписка** создаётся в базе со статусом `PastDue` и `providerData.pending: true`
5. **Пользователь перенаправляется** на платёжную страницу Т-Банка (`checkoutUrl`)
6. **Пользователь оплачивает** на стороне Т-Банка
7. **Т-Банк присылает вебхук** на `/_tbank-subscriptions/api/v1/webhooks/tbank`
8. **Обработчик вебхука** проверяет подпись, обновляет подписку: `status → Active`, `pending → false`, сохраняет `rebillId` для будущих списаний
9. **Фронтенд опрашивает** `getCheckoutStatus` → видит `pending: false` → подписка активна
10. **Планировщик** периодически проверяет истёкшие подписки и пытается провести `chargeRecurrent` для продления

### Смена тарифа (повышение/понижение)

- Старая подписка **НЕ отменяется сразу** — она помечается `pendingReplacement: true`
- Создаётся новый платёж для нового тарифа
- Когда вебхук подтверждает оплату, старая подписка отменяется автоматически
- Если пользователь не оплатил, старая подписка остаётся активной

### Почему вебхуки всегда возвращают 200 OK

Т-Банк повторяет доставку вебхука при любом ответе кроме 200. Чтобы избежать дублирования:

- **Ошибка проверки подписи** → `200 OK` (тихо игнорируем невалидные вебхуки)
- **Не найдена pending-подписка** → `200 OK` (логируется как ошибка, не повторяется)
- **Успешная обработка** → `200 OK`
- **Любая ошибка** → `200 OK` (ошибки логируются, но не возвращаются Т-Банку)

Это гарантирует, что вебхуки никогда не повторяются, предотвращая дублирование списаний и повреждение состояния подписок.

### Продление подписок (Планировщик)

- Запускается с настраиваемым интервалом (по умолчанию: 60 минут)
- Находит подписки, у которых `periodEnd <= now` и присутствует `rebillId`
- Вызывает `tbank.chargeRecurrent(PaymentId, RebillId)` для списания с сохранённой карты
- При успехе: продлевает `periodEnd` на 30 дней
- При неудаче: помечает подписку как отменённую

## Локальное тестирование

### Имитация вебхука

Используйте [webhook-tester.shippeo.com](https://webhook-tester.shippeo.com) или curl напрямую:

```bash
curl -X POST http://localhost:8087/_tbank-subscriptions/api/v1/webhooks/tbank \
  -H "Content-Type: application/json" \
  -d '{
    "TerminalKey": "1774599770012DEMO",
    "OrderId": "8h2k9m-1-lx7abcde-3gh7",
    "Success": true,
    "Status": "CONFIRMED",
    "PaymentId": "8458846078",
    "Amount": 29900,
    "RebillId": "test-rebill-123",
    "CustomerKey": "<accountUuid>",
    "Token": "<valid-token>"
  }'
```

> **Примечание:** `Token` в вебхуке — это криптографическая подпись, генерируемая Т-Банком. Для локального тестирования с демо-терминалом можно временно отключить проверку подписи в `utils.ts`, вернув `true`.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `4042` | Порт HTTP-сервера |
| `SECRET` | — | Секрет для генерации служебных токенов |
| `ACCOUNTS_URL` | — | URL сервиса аккаунтов |
| `FRONT_URL` | — | URL фронтенда (для URL-редиректов) |
| `TBANK_TERMINAL_KEY` | — | Ключ терминала Т-Банка |
| `TBANK_PASSWORD` | — | Пароль терминала Т-Банка |
| `TBANK_URL` | — | URL API Т-Банка |
| `TBANK_SUBSCRIPTION_PLANS` | — | Тарифы в формате `plan@type:суммаВКопейках;...` |
| `SCHEDULER_INTERVAL_MINUTES` | `60` | Интервал проверки продлений |

## Ключевые файлы

| Файл | Назначение |
|---|---|
| `src/server.ts` | HTTP API: создание, отмена, обновление, обработка вебхуков |
| `src/scheduler.ts` | Логика периодического продления подписок |
| `src/storage.ts` | Операции с БД через AccountClient |
| `src/utils.ts` | Вспомогательные функции: генерация orderId, проверка вебхуков, парсинг тарифов |
| `src/types.ts` | TypeScript-типы для запросов и вебхуков |
| `src/config.ts` | Парсинг конфигурации из переменных окружения |
