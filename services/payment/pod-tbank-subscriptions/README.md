# TBank Subscriptions Service (`pod-tbank-subscriptions`)

## Overview

The TBank Subscriptions service handles the full lifecycle of TBank (Tinkoff) recurring payments for the Foundation platform. It acts as an intermediary between the platform's payment provider (`pod-payment`) and the TBank Acquiring API.

## How It Works

### Flow

1. **User selects a plan** on the billing page → `pod-payment` receives a `createSubscription` request
2. **`pod-payment` delegates** to this service via HTTP (`POST /api/v1/subscriptions`)
3. **Payment is initiated** via `tbank.initPayment()` with `Recurrent: 'Y'` (enables recurring charges)
4. **Pending subscription** is created in the database with `status: PastDue` and `providerData.pending: true`
5. **User is redirected** to the TBank payment page (`checkoutUrl`)
6. **User completes payment** on TBank's side
7. **TBank sends a webhook** to `/_tbank-subscriptions/api/v1/webhooks/tbank`
8. **Webhook handler** validates the signature, updates subscription: `status → Active`, `pending → false`, saves `rebillId` for future charges
9. **Frontend polls** `getCheckoutStatus` → sees `pending: false` → subscription is active
10. **Scheduler** periodically checks for expired subscriptions and attempts `chargeRecurrent` to renew them

### Plan Change (Upgrade/Downgrade)

- Old subscription is **NOT canceled immediately** — it's marked with `pendingReplacement: true`
- A new payment is created for the new plan
- When the webhook confirms payment, the old subscription is canceled automatically
- If the user never pays, the old subscription remains active

### Why Webhooks Always Return 200 OK

TBank's webhook delivery system retries on non-200 responses. To prevent duplicate processing:

- **Signature validation failures** → `200 OK` (silently ignore invalid webhooks)
- **Missing pending subscription** → `200 OK` (logged as error, not retried)
- **Successful processing** → `200 OK`
- **Any error** → `200 OK` (errors are logged, not exposed to TBank)

This ensures webhooks are never retried, preventing duplicate charges or subscription state corruption.

### Subscription Renewal (Scheduler)

- Runs on a configurable interval (default: 60 minutes)
- Finds subscriptions where `periodEnd <= now` and `rebillId` is present
- Calls `tbank.chargeRecurrent(PaymentId, RebillId)` to charge the saved card
- On success: extends `periodEnd` by 30 days
- On failure: marks subscription as canceled

## Local Testing

### Prerequisites

```bash
# Start all services
docker compose -f dev/docker-compose.yaml up -d
```

### 1. Test Subscription Creation

```bash
# Replace <workspace> with your workspace URL slug, get a valid token first
curl -X POST http://localhost:8087/_payment/api/v1/subscriptions/<workspace>/subscribe \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"type": "tier", "plan": "start", "customerEmail": "test@example.com"}'
```

Response:
```json
{"checkoutId": "8h2k9m-1-lx7abcde-3gh7", "checkoutUrl": "https://securepay.tinkoff.ru/..."}
```

### Simulate a Webhook

Use [webhook-tester.shippeo.com](https://webhook-tester.shippeo.com) or curl directly:

```bash
# Get the webhook endpoint from webhook-tester, configure it in the code, or use ngrok
curl -X POST http://localhost:8087/_tbank-subscriptions/api/v1/webhooks/tbank \
  -H "Content-Type: application/json" \
  -d '{
    "TerminalKey": "1774599770012DEMO",
    "OrderId": "8h2k9m-1-lx7abcde-3gh7",
    "Success": true,
    "Status": "CONFIRMED",
    "PaymentId": "8458846078",
    "Amount": 29900,
    "RebillId": "test-rebill-123",
    "CustomerKey": "<accountUuid>",
    "Token": "<valid-token>"
  }'
```

> **Note:** The `Token` in the webhook is a cryptographic signature generated by TBank. For local testing with the demo terminal, you can temporarily skip signature verification in `utils.ts` by returning `true`.

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `PORT` | `4042` | HTTP server port |
| `SECRET` | — | Service secret for token generation |
| `ACCOUNTS_URL` | — | Account service URL |
| `FRONT_URL` | — | Frontend URL (for redirect URLs) |
| `TBANK_TERMINAL_KEY` | — | TBank terminal key |
| `TBANK_PASSWORD` | — | TBank terminal password |
| `TBANK_URL` | — | TBank API URL |
| `TBANK_SUBSCRIPTION_PLANS` | — | Plans in format `plan@type:amountInCents;...` |
| `SCHEDULER_INTERVAL_MINUTES` | `60` | How often to check for renewals |

## Key Files

| File | Purpose |
|---|---|
| `src/server.ts` | HTTP API: create, cancel, update, webhook handlers |
| `src/scheduler.ts` | Periodic subscription renewal logic |
| `src/storage.ts` | Database operations via AccountClient |
| `src/utils.ts` | Helpers: orderId generation, webhook verification, plan parsing |
| `src/types.ts` | TypeScript types for requests and webhooks |
| `src/config.ts` | Configuration parsing from environment |
