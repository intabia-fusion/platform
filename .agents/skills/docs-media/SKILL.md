# Скриншоты и видео для документации

Снимаем только по согласию пользователя: формат и подъём стенда каждый раз подтверждаются.
Текст страницы и карта - скилл `docs-sync`.

## Что нужно

- Стенд `--docs` выглядит как прод (`tests/docker-compose.docs.yaml`: брендинг Интабии, темы,
  `DISABLED_FEATURES` прода), поэтому sanity-тесты на нём не гонять; после съёмки, если пользователю
  нужен sanity-стенд, - обычный `./prepare-pg.sh`.
- Демо-стенд: `cd tests && ./prepare-pg.sh --docs` - sanity-стенд плюс воркспейс `demo-ws` с
  аккаунтами `demo1..demo4`, наполненный командой `generate-demo-data`. Проверка, что стенд `docs`
  уже есть в коде: `grep -n "demo-ws" dev/test-base/src/stands.ts`. Нет - сказать пользователю, что
  этап демо-данных (TSK-2026-10-21-docs-sync-04/05) не сделан, и остановиться: тестовые данные
  `sanity-ws` в документацию не снимаем.
- `record.js` из `feature-video`: `FEATURE_VIDEO` (по умолчанию
  `../platform-tasks/.agents/skills/feature-video`). Нужны `h.login`, `VIDEO=none`, `h.shot(label, { region })`, `h.crop`,
  `CLEAN_SHOTS=1` (TSK-2026-10-21-docs-sync-07): `grep -n "async login\|CLEAN_SHOTS" $FEATURE_VIDEO/record.js`.
  Нет - остановиться и сказать.
- Помощники сценария, ловушки (попапы, телефон, загрузка файлов) - `$FEATURE_VIDEO/SKILL.md`.

## Стиль - один на всю документацию

- Два набора: ru - воркспейс `demo-ws`, вход `demo1` (Анна Смирнова), `VIDEO_LANG=ru`; en - воркспейс
  `demo-ws-en`, вход `demo-en1`, `VIDEO_LANG=en`. Интерфейс, данные и формат дат/времени в кадре - на языке страницы:
  локаль браузера `ru-RU`/`en-US` (иначе в ru-кадре "5:46 PM").
  У страницы есть en-версия - снимаем оба набора, без исключений. Светлая тема.
- Десктоп 1440x900, deviceScaleFactor 2. В кадре - область, о которой речь (панель, диалог, меню,
  список) с небольшим контекстом вокруг; полный экран приложения - только для обзорного кадра раздела.
- Элемент, о котором речь (диалог, меню, попап, панель), - всегда целиком, без обрезки сверху и снизу:
  `frame` сам растёт под область; диалог выше экрана - снимать с `VIEWPORT_HEIGHT=1200` (или сколько нужно).
- Кадр не ретушировать: ничего не вырезать и не закрашивать из того, что показывает интерфейс. Стенд `--docs` идёт
  с `DISABLED_FEATURES` прода; если в кадре видно выключенное - спросить пользователя (баг продукта или
  стенда), а не править картинку.
- Не вводить текст в существующие документы и сообщения демо-данных (синтетический клик мимо портит их);
  для кадра с вводом - создать свою сущность (задачу, документ, сообщение в канале "разработка").
- Картинка помещается в экран: высота не больше 16:10 от ширины (`h.shot`/`h.crop` режут по `ratio = 0.625`,
  верх сохраняется). Высокую область - снимать её верхнюю часть или другую, более широкую область.
- В кадре - результат действия на демо-данных, без плашек сценария, курсора и тестовых имён.
- Вход в аккаунт в кадр не попадает: `h.login` входит до начала записи, видео и снимки начинаются в
  воркбенче. Исключение - страницы про сам вход и регистрацию.

Формат - самый простой, которого хватает:

| Что показать | Формат |
|---|---|
| одно состояние | один скриншот |
| последовательность 2-6 шагов | скриншоты шагов, переключаемые вкладками (ниже) |
| движение: drag&drop, анимация, живой процесс, без которого шаги непонятны | видео: без музыки, до 30 с, обрезано по области, как скриншот |

Картинки - компонентом `Shot` (`src/components/Shot.astro`): один масштаб на весь сайт, 0.7 от размера
интерфейса (ширина файла x 0.35), маленькая область не растягивается на колонку, клик - полный размер. Шаги -
вкладки Starlight в обёртке `ScreenshotSteps` (`src/components/ScreenshotSteps.astro`: под картинкой
"← Назад / Шаг N из M / Далее →"):

```mdx
import { Tabs, TabItem } from "@astrojs/starlight/components";
import ScreenshotSteps from "../../../../components/ScreenshotSteps.astro";
import Shot from "../../../../components/Shot.astro";

<ScreenshotSteps>
<Tabs>
  <TabItem label="1. Открыть меню"><Shot src={step1} alt="..." /></TabItem>
  <TabItem label="2. Выбрать этап"><Shot src={step2} alt="..." /></TabItem>
</Tabs>
</ScreenshotSteps>
```

Переснятая страница - та, в которой нет импортов из старых папок и старых видео. Что осталось:

```bash
cd ../platform-docs/src/content/docs
grep -rlE "assets/screenshots/(huly|eqms)/|<LocalVideo id=['\"][^/'\"]+['\"]" ru en | sort   # старые видео - id без папки
```

Страницы фич со статусом `off` не переснимаем.

Временные скрипты агентов (Playwright-пробы стенда) - только в `.tmp-shots/` (в `.gitignore`), Playwright
- по абсолютному пути `require('<foundation>/tests/sanity/node_modules/@playwright/test')`: файлы в `tests/sanity`
попадают в коммиты пользователя.

## Роли

| Работа | Роль | Параллельно | Что отдаёт |
|---|---|---|---|
| Поиск: шаги страницы, кандидаты селекторов (`data-id`, тексты из `lang/*.json`), объекты генератора | сборщик фактов | до 5 | только ссылки: `file:line`, тексты, имена объектов; не выбирает |
| Сценарии `record.js`, подстановка картинок в страницы | исполнитель | до 2, страницы не пересекаются | сценарий, дифф страницы |
| Финальная проверка | проверяющий | 1, новый независимый проверяющий на каждый круг | вердикт по каждому снимку |

Роли назначать через доступный инструмент делегирования. Лимиты - на весь скилл: в задании писать "своих под-агентов не запускай".
Запись идёт последовательно: стенд один. При делегировании основной поток запускает `record.js`, сам код не читает.
Проверяющий получает только снимки, текст страницы и дифф - не историю сессии. Два круга без согласия -
решает пользователь.
Если делегирование недоступно, выполнять этапы последовательно и прямо указать, что независимой проверки не было.

## Порядок

1. **Согласовать** доступным инструментом вопросов: страницы и формат каждого места по таблице "Формат" (скриншот /
   шаги вкладками / видео); видео - только с обоснованием, зачем движение. en-набор не спрашиваем: он
   обязателен, если у страницы есть en-версия.
2. **Стенд.** Даты демо-данных считаются от дня подъёма стенда: снимаем в тот же день, иначе в кадре
   "Вчера" и просроченные сроки. Порт 8083 общий с sanity-прогонами, `prepare-pg.sh` их убивает. Проверить
   `docker ps --format '{{.Names}}' | grep -i sanity` и `pgrep -fl playwright`; идёт прогон или
   стенд поднят не с `--docs` - спросить пользователя, прежде чем пересоздавать. Без согласия стенд
   не трогать.
3. **Факты** (сборщик фактов, по странице на исполнителя):
   > Страница `<platform-docs>/src/content/docs/ru/<раздел>/<страница>.mdx`. Выпиши места, где стоит
   > или должна стоять картинка/видео, и что на ней видно по тексту страницы. Для каждого шага найди
   > в `<foundation>` селектор: `data-id` или текст из `lang/ru.json` (ключ, `file:line`), и перечисли
   > демо-объекты из `tests/demo-ws/`, `tests/demo-ws.data.yaml` (проекты, задачи, документы) с путями.
   > Ничего не выбирай и не оценивай - выбор делает исполнитель.
4. **Сценарий** (исполнитель): `.tmp-shots/docs-media/<раздел>-<страница>.js`,
   `module.exports = async (h) => { await h.login({...}); ... }`. Кадр - результат действия, а не
   пустой диалог: задача заведена, меню раскрыто, фильтр применён. Перед снимком - `h.escape()`
   лишних попапов.
5. **Запуск** из корня foundation:

   ```bash
   STAND_URL=http://localhost:8083 VIDEO_LANG=ru VIDEO=none CLEAN_SHOTS=1 KEEP_SHOTS=1 \
     node $FEATURE_VIDEO/record.js .tmp-shots/docs-media/<раздел>-<страница>.js desktop
   ```

   Видео - только если формат выше требует; без `VIDEO=none` и `KEEP_SHOTS`, с `VIDEO_MUSIC=none`, в сценарии `h.crop(<локатор области>)` после того, как раскладка установилась, до 30 с. Падение - сначала
   `error.png`: ошибка сценария - чинить сценарий; ошибка фичи - находка, сообщить пользователю.
6. **Файлы в platform-docs**:
   - скриншот - `src/assets/screenshots/<раздел>/<страница>-<метка>.png` (en -
     `<страница>-<метка>-en.png`); сжать тем, что есть: `command -v oxipng pngquant`;
   - видео - `public/videos/<раздел>/<страница>.mp4`, вставка `<LocalVideo id="<раздел>/<страница>"/>`;
   - в mdx заменить импорт, `alt` - что на снимке, по-русски (en - по-английски);
   - старые картинки страницы (из папок не по разделу, от апстрима) удалить, если на них больше никто
     не ссылается:
     `grep -rn '<имя файла>' src/`.
7. **Проверка** (проверяющий, чистый контекст). На вход: снимки (листами по 3-6 через PIL), текст
   страницы, дифф. Проверить: снимок показывает то, что написано рядом; интерфейс на языке
   страницы; нет брендинга апстрима, плашек сценария, тестовых имён (`John Appleseed`, `Test issue`), почт и токенов;
   данные демо-воркспейса, а не пустые экраны; `alt` соответствует снимку.
8. **Сборка**: `cd ../platform-docs && pnpm build`.

## Итог

Пользователю: какие снимки и видео заменены (пути), что удалено, вердикт проверяющего или отсутствие независимой проверки, найденные дефекты
фич. `.tmp-shots/` в `.gitignore`, в коммит не идёт. Коммиты - только по просьбе.
