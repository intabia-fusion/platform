# Макет -> задача -> код

## 1. Собрать вход

- Прочитать задачу и комментарии через Fusion, если работа привязана к задаче.
- Найти указанные истории и их исходники в `dev/storybook/src/`: `.stories.ts` и используемые ими Svelte-компоненты и данные. Уточнить нужную историю, если макет не указан и его нельзя однозначно определить.
- Запустить `pnpm -w storybook:dev` и открыть нужную историю на `localhost:6006`. Проверить состояния, тексты, тему и размеры, которые относятся к задаче. Сохранить скриншоты для сравнения при необходимости.
- Истории в Storybook могут быть прототипами. Не считать отсутствие состояния или данных в истории требованием к продукту; сверить их с задачей.

## 2. Сопоставить макет с кодом

- Для каждого экрана сопоставить элементы с продуктовым кодом. Начать с `docs/features/README.md` и карты соответствующей области.
- Искать существующие компоненты в `docs/ui-components/` и коде. Определить изменения модели, данных, локализаций и интерфейса.
- Зафиксировать отличия текущего продукта от целевого экрана и открытые вопросы. Использовать реальные состояния продукта, а не только демонстрационные данные истории.

## 3. План и задача

- Если нужен план в foundation-tasks, использовать `spec-new`.
- Если пользователь попросил обновить задачу Fusion, приложить согласованные описание, шаги и скриншоты. Соблюдать инструкции навыка `fusion`.

## 4. Реализация и проверка

- При работе по плану foundation-tasks использовать `spec-implement`.
- Сверить реализованный экран со Storybook на одинаковых размерах и в соответствующих состояниях. Для расхождений размеров и цветов использовать computed styles и DOM-замеры.
- Проверить продукт на стенде и выполнить проверку изменённых пакетов: `pnpm build:lint --to <пакет>`. Соблюдать дополнительные проверки из AGENTS.md для общих компонентов.
- Обновлять истории вручную только когда это входит в задачу. Отдельная генерация историй не требуется.
- В отчёте указать реализованные пункты и то, что не удалось проверить.
