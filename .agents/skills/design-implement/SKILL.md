# Макет -> задача -> код

Макеты лежат кодом в `dev/penpot/`: файл задачи описан в `dev/design/design.json`, экраны - в `dev/design/screens/<задача>/`. Страницы `as-is` повторяют продукт, страницы `to-be` - то, что надо сделать. Как работать с Penpot - `docs/penpot.md`.

## Кто делает работу

Основной контекст дорогой: скриншоты, DOM-замеры, JSON `diff` и вывод сборки его быстро забивают. Поэтому:

- Тяжёлые шаги поручить исполнителю через доступный инструмент делегирования:
  - сбор и разбор `design:diff`;
  - замер стенда (DOM, стили, иконки);
  - правка скриптов `dev/penpot`;
  - сборка;
  - экспорт и сравнение скриншотов.
- Исполнитель получает самодостаточное задание: файл Penpot, страницу, пути скриптов, что проверить. Возвращает таблицу "что -> где изменено", не скриншоты и не сырые дампы.
- Независимые части запускать параллельно, если инструмент позволяет: разные экраны, разные комментарии.
- Основной поток решает: что менять в компоненте, а что в экране, что спросить у человека. Затем проверяет итог по короткому отчёту исполнителя.
- Если делегирование недоступно, выполнять шаги последовательно и прямо указать, что независимой проверки не было.
- Одна вкладка Penpot на MCP-ключ: исполнители не должны одновременно собирать разные файлы. Сборки идут последовательно, правки скриптов - параллельно, если инструмент позволяет.

## 1. Собрать вход

- Задача: `read_issue` и `list_issue_comments` (fusion MCP).
- Макет: запись в `design.json` с номером задачи и её скрипты. Читать скрипты - это точное описание экрана: данные, состояния, тексты.
- Есть ли не перенесённые правки в Penpot: открыть файл, `pnpm -w design:diff`. Правки или комментарии есть - сначала навык `penpot-ingest`, иначе реализуется устаревший макет.
- Скриншоты фреймов для задачи и сравнения:
  1. Файл открыт и подключён.
  2. `node dev/penpot/penpot.mjs run` со скриптом `return penpot.root.children.map((s) => [s.name, s.id])` на нужной странице.
  3. `node dev/penpot/penpot.mjs shot <id> dev/penpot/files/shots/<задача>/<имя>.png`.

## 2. Сопоставить макет с кодом

Для каждого to-be фрейма составить таблицу "элемент макета -> где в коде":

- Компоненты:
  - Имена kit повторяют `@hcengineering/ui/kit`: `Button` kind/size - это те же props.
  - Остальное искать по каталогам `docs/ui-components/` (`ui-kit.md`, `packages-ui.md`, `packages-presentation.md`, `view-resources.md`).
  - Нового компонента нет в ките - он делается в ките (`packages/ui/src/ui-kit/`), а не в плагине. Правила - в `ui-kit.md`.
- Фича: `docs/features/README.md` и `docs/features/<область>.md` - пакеты, модель, точки входа. Например, канбан - `plugins/tracker-resources/.../KanbanView.svelte` и `packages/kanban`.
- Данные: что из макета требует модели (новые классы, атрибуты, миграции), что - только UI.
- Тексты: каждый новый текст - ключ i18n во всех локалях `lang/` пакета.
- Отличие as-is от to-be на соседних страницах - это и есть объём работ.

## 3. План и задача

- План: навык `spec-new`, документ в foundation-tasks с задачами `TSK-...`, ссылкой на файл Penpot и путями скриншотов.
- В задачу Fusion по просьбе человека:
  - кратко, что делаем, и таблица сравнения было/стало;
  - скриншоты через `add_issue_attachment`;
  - чек-лист `- [ ]` по пунктам плана.
- Описание задачи и вложения меняют общую задачу. Перед записью показать текст человеку и получить согласие.

## 4. Реализация

- По плану через навык `spec-implement`, пункт за пунктом.
- После каждого экрана - сверка с макетом:
  1. Поднять стенд (`docs/testing.md`, sanity-стенд `localhost:8083`).
  2. Открыть экран в браузере и снять скриншот.
  3. Положить рядом со скриншотом фрейма из шага 1.
  4. Расхождения в цветах и отступах проверить через computed styles, а не на глаз.
- Проверка сборки: `pnpm build:lint --to <пакет>`.

## 5. Замкнуть макет

- После реализации перенести то, что стало продуктом, на страницу `as-is`: as-is снова повторяет стенд, to-be остаётся историей решения или удаляется по согласию человека.
- Пересобрать: `pnpm -w design:build "<файл>"`.
- Отчёт: что сделано по каждому пункту, что не сверено со стендом, что отложено.
